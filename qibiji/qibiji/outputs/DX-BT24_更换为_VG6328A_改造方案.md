# DX-BT24 更换为 VG6328A 改造方案

技术改造说明 · 2026-10-14（第二版）

> 依据：沃进 VG6328A-Pro 官方《串口操作说明》v1.0.0（更新日期 2025-05-20，doc.cloudpeaks.cn）+ lanya 模块测试工具联调实测。
>
> 适用工程：`qibiji`（主固件）、`qibiji_init`（出厂固件 + Qt 上位机）、`Admin.NET-v2/App`（uni-app）、`Admin.NET-v2/MiniProgram`（微信小程序）、`lanya-ceshi/lanya`（模块测试工具）及配套文档。
>
> 相关文档：[DX-BT24 与 VG6328A 透传字节差异对比](./DX-BT24_与_VG6328A_透传字节差异对比.md)

## 一、结论

换用的是 **VG6328A-Pro**（BLE 从机 + SPP 蓝牙，2.4 GHz，14.5 × 11.5 mm）。它有**三处与 DX-BT24 不一样，其中两处不改就一定联不通**：

| # | 差异 | 后果 | 处理 |
| --- | --- | --- | --- |
| 1 | **AT 命令必须以 `\r\n\0` 结尾**（回车+换行+空格/NUL） | 只发 `AT\r\n` 模块完全不应答，表现为"TX 有、RX 永远空" | 发送端追加 `\0` |
| 2 | **成功返回 `+OK`、失败返回 `+ERP`**（不是裸 `OK`） | 按 `OK` 判定会误判成无应答 | 判定兼容 `+OK`/`+ERP` |
| 3 | **GATT 特征方向与 BT24 相反**：`FFE1 = Write`、`FFE2 = Notify` | App 若沿用"FFE1 订阅、FFE2 写入"，订阅与写入都会失败 | App/小程序改为**按属性自动发现**特征 |

**不必改动**的部分：SBF-20 线帧协议（`SOF=0x55`、≤19 B、逐对请求响应）、服务 UUID 仍是 `FFE0`、UART 接线方式（TX/RX 交叉 + 共地）、近场配置页交互与 JSON 读写语义。

## 二、两代模组对照

| 对比项 | DX-BT24 | VG6328A-Pro |
| --- | --- | --- |
| 蓝牙角色 | 单模 BLE 从机（DA14531） | BLE 从机 + SPP 经典蓝牙（AC6328A） |
| 串口默认参数 | 9600 8N1 | **115200**，无校验，1 位停止位 |
| 命令/应答结束符 | `\r\n`（AT 模式） | **`\r\n\0`** |
| 成功 / 失败返回 | `OK` / `ERROR` | **`+OK` / `+ERP`** |
| 读蓝牙地址 | `AT+LADDR` → `+LADDR=48872D8429CB` | `AT+MAC?` → `+MAC:${12位hex}` |
| 读蓝牙名称 | `AT+NAME` | `AT+NAM?` → `+NAM:${name}`（默认 `VG7439-${MAC后4字节}`） |
| 读版本 | `AT+VERSION` | `AT+VER?` → `+VER:${version}` |
| 透传服务 | `FFE0` | `FFE0`（可用 `AT+ULEN` 切 128bit） |
| 手机 → 模块（写） | `FFE2` | **`FFE1`**（write / write no response） |
| 模块 → 手机（通知） | `FFE1` | **`FFE2`**（notify） |
| 连接鉴权 | 私有 4 位密码（`AT+OPASS`/`AT+APASS`） | **无**；AT 指令另有独立服务 `AA00` |
| 低功耗 | 广播间隔 + 连接间隔 | `AT+LPM` / `AT+PCT` + **PA9 引脚**唤醒 |
| 引脚 | VCC/GND/TXD/RXD（+状态脚） | 1 RX、2 TX、3 GND、4 VCC(1.8–3.6 V)、5 PA9 |

## 三、本次联调实测与排障记录（重要经验）

用 `lanya` 测试工具直连模组复现并定位问题，过程如下：

1. **现象**：TX 有记录（字节确实写进串口），但 RX **全程零字节**——连杂字节都没有。
2. **缩小范围**：扫描"2 个端口 × 6 档波特率"共 12 组，全部静默；说明不是波特率问题（波特率错通常会收到乱码而不是绝对静默）。
3. **隔离适配器**：回环自测（把适配器 TX/RX 短接再发数据），确认适配器、驱动、工具链路本身正常。
4. **根因**：命令缺少 `\r\n\0` 结尾 → 模块把整条命令当噪声丢弃，因此一个字节都不回。
5. **修正后**：`AT\r\n\0` → `+OK\r\n\0`，一键检测全绿。

> 结论：**"TX 有、RX 空" 在 VG6328A 上首先查结束符 `\r\n\0`**。这条要写进产线与售后排障手册。

排障顺序（已固化进测试工具）：

| 现象 | 首选排查 |
| --- | --- |
| TX 有、RX 全空 | 命令是否带 `\r\n\0`；TX/RX 是否交叉；适配器 RX 是否接线；模块是否上电 |
| 收到回显但判定失败 | 是否按 `+OK`/`+ERP` 判定；读指令是否用 `AT+CMD?` 形式 |
| 扫描某端口有回显但无 `+OK` | 波特率/结束符不匹配，或该端口接的是别的设备 |
| 手机搜不到模块 | `AT+ADE?` 广播是否使能（默认打开；手册第 10/11 条） |
| 模块连上手机后串口没反应 | `AT+LPM` 是否处于低功耗（低功耗时串口无法接收，需 PA9 下降沿唤醒） |

## 四、改造清单

### 4.1 下位机固件（`qibiji`、`qibiji_init`）

1. **串口波特率**：模组出厂 115200，固件当前是 9600，二选一：
   - 推荐：固件改 115200（在 `usart.h` 定义 `BLE_UART_BAUD`，两处 `uart3_init()` 引用），新出厂统一，近场读写提速约 12 倍；
   - 或：出厂用 `AT+BPS=9600,0,1` 把模组设成 9600，固件保持不动。
2. **SBF-20 解析器不改**：它按 `0x55` 同步、逐字节喂帧，天然容忍模组的开机打印（`+POWERON`、`+MTU-xx`）与 `\r\n\0` 杂字节。
3. **时序常量不改**：`SBF20_HALF_PKT_MS=100`、`SBF20_PAIR_TIMEOUT_MS=500` 在 115200 下余量充足。
4. **缓冲不变式**：`DMA_Rec3_Len=256` ≥ 模组串口单包上限，无需扩容。
5. 固件不控制模组使能脚；PA9 只有用低功耗时才需要接 MCU GPIO。

### 4.2 App（uni-app）与微信小程序

1. **特征选择必须改成按属性自动发现**（关键，因为 FFE1/FFE2 与 BT24 相反）：
   - 服务优先取 `FFE0`，找不到再遍历其它服务（跳过 `1800/1801/180A/180F` 标准服务）；
   - 在同一服务内：**收 = 第一个 notify/indicate 特征**，**发 = 第一个 write/writeNoResponse 特征**；
   - 不要再用 "含 ffe1 就是通知、含 ffe2 就是写入" 的写法。
2. 写类型优先 `writeNoResponse`（模组 `writeMode` 默认 0 = 写无需确认），保留 `write` 回退链。
3. **关闭 BT24 私有密码握手**（VG6328A 无此机制）：`BT24_AUTH.enabled = false`；建议把密码握手降级为"旧模组兜底"——连接后先探活，失败再尝试握手。
4. MTU：模组连接后会主动打印 `+MTU-${len}`，App 侧继续沿用 `setBLEMTU`（华为/鸿蒙跳过）与 ≤19 B 线帧，无需分包逻辑。
5. 两处客户端逐文件镜像同一改动（App 为 ESM、小程序为 CommonJS）。

### 4.3 出厂配置工具（`qibiji_init` 的 Qt 上位机）

1. `{"op":"at3"}` 原始 AT 透传保留（MCU 侧 `sbf20_app.c` 支持 `at`/`at3`）。
2. 三个快捷按钮的指令改为手册原文：地址 `AT+MAC?`、名称 `AT+NAM?`、版本 `AT+VER?`。
3. **透传链路也要带 `\r\n\0`**：`at3` 由 MCU 在命令尾部补 `\r\n\0`（或在透传层配置），否则同样静默。
4. `bleMacOf()` 解析已兼容 `+MAC:D0000C2E885F` 这种无分隔 12 位 hex，无需改动。
5. 蓝牙页提示文案补 "模块可能处于低功耗（`AT+LPM`），此时串口不收命令，需 PA9 下降沿唤醒"。

## 五、VG6328A-Pro AT 速查表（只读诊断相关）

> 通用规则：命令区分大小写；**命令与应答都以 `\r\n\0` 结束**；读操作用 `AT+CMD?`；成功 `+OK`，失败 `+ERP`；参数掉电保存，别频繁写。

| 用途 | 指令 | 返回值 |
| --- | --- | --- |
| AT 测试 | `AT` | `+OK` |
| 蓝牙角色 | `AT+BTM?` | `+BTM:${mode}`（0 从机 / 1 SPP / 2 主机，仅 Plus） |
| BLE 广播名称 | `AT+NAM?` | `+NAM:${name}`（≤16 字符） |
| 串口波特率 | `AT+BPS?` | `+BPS:${baud},${parity},${stop}` |
| BLE 从机 MAC | `AT+MAC?` | `+MAC:${12位hex}` |
| 固件版本 | `AT+VER?` | `+VER:${version}` |
| 连接状态 | `AT+STA?` | `+STA:${bleSl},${sppSl},${bleMs}`（1 未连接 / 2 已连接） |
| BLE 广播使能 | `AT+ADE?` | `+ADE:${0\|1}`（从机模式默认打开） |
| 服务 UUID 长度 | `AT+ULEN?` | `+ULEN:$(16|128)` |
| 16bit 透传 UUID | `AT+UUID?` | `+UUID:${writeSrv},${writeChar},${notifySrv},${notifyChar},${writeMode}` |
| 128bit 透传 UUID | `AT+UUIDX?` | `+UUIDX:...`（默认 Nordic 串口风格） |
| 低功耗控制 | `AT+LPM?` / `AT+LPM=1` | `+LPM:${mode}` |
| 低功耗模式 | `AT+PCT?` / `AT+PCT=1` | `+PCT:${type}` |

模块主动打印（可用来判断链路是否通）：`+POWERON`、`+MTU-${len}`、`+CONNECT-${ROLE}-${INDEX}`、`+DISCONNECT-...`、`+WRITE OK`、`+UUID NOTIFY OK`、`+UUID WRITE OK`。

> 注：站点 `atProtocol` / `__atProtocol_lp` 页另有一套固件方言（`AT+ENAT` 进命令模式，`AT+VERS`/`AT+CONN`/`AT+LEGA`/`AT+LEGN`/`AT+SPGA`/`AT+SPGN`，普通 `\r\n` 结尾）。若现场遇到的是那版固件，把测试工具的候选指令表追加这些命令即可，架构不用改。

## 六、GATT 与 UUID

| 服务 | 特征 | 属性 | 方向 |
| --- | --- | --- | --- |
| `0xFFE0` 数据透传（默认 16bit） | `0xFFE1` | write / write no response | App → 模块 → 串口 TXD |
| | `0xFFE2` | notify | 串口 RXD → 模块 → App |
| `0x6E400001-B5A3-F393-E0A9-E50E24DCCA9E`（128bit 模式） | `...0002` | write / write no response | 同上 |
| | `...0003` | notify | 同上 |
| `0xAA00` AT 命令服务 | `0xAA01` | notify | 模块 → App（AT 返回值） |
| | `0xAA02` | write | App → 模块（发 AT 命令，**不需要** `\r\n\0` 后缀） |

**与 BT24 的差异必须记牢**：BT24 是 `FFE1=Notify、FFE2=Write`，VG6328A-Pro 是 `FFE1=Write、FFE2=Notify`，同名特征方向相反。因此 App/小程序不能写死，必须按属性选特征。

`0xAA00` 那组是指令通道，不是数据通道；近场配置仍走 `FFE0`。

## 七、低功耗实现（对应手册第 25/34 条）

| 模式 | 指令 | 行为 |
| --- | --- | --- |
| 手动进低功耗 | `AT+LPM=1` | 进入低功耗；**此时串口无法接收**，但收到蓝牙数据仍能正常打印；靠 **PA9 下降沿唤醒**；`AT+LPM=0` 退出 |
| PA9 电平控制 | `AT+PCT=1`（V1.0.7+） | 低功耗由 PA9 电平决定：高电平=低功耗，低电平=正常工作 |

ARM 侧对应工作量：

1. 把 **PA9 引到 MCU 的一个 GPIO**（模组 5 脚定义的第 5 脚），低功耗唤醒/控制都要用它。
2. 若走 `AT+LPM=1`：进低功耗后串口命令收不进去，唤醒必须靠 PA9 下降沿；MCU 侧只需在需要通信前拉一次 PA9，不需要把 USART3 改成中断接收。
3. 若走 `AT+PCT=1`：MCU 用 GPIO 电平直接控制模块工作/休眠，逻辑最简单，适合"平时休眠、配置时唤醒"的闸门控制器。
4. 若还想让 MCU 自己也进 Sleep/STOP：注意 IWDG 在 STOP 下仍计数（当前约 3.18 s），且 USART3 的 DMA 在 STOP 下不工作，需改为 PD9 边沿唤醒 + 唤醒后重建 USART3/DMA。
5. App 侧"用完即断"已经做到（近场页 `onUnmounted` → `cleanup()` → 断开并关闭适配器），不需要额外改动。

## 九、出厂与现场操作步骤

**新产（VG6328A-Pro）**

1. 接线：模组 `RX` ← MCU `PD8(TX)`，模组 `TX` → MCU `PD9(RX)`，`GND` 共地，`VCC` 接 3.3 V（1.8–3.6 V）；PA9 按低功耗方案决定是否接 MCU GPIO。
2. 上电后用 lanya 工具确认：`AT` 有 `+OK`、`AT+MAC?` 有地址、`AT+VER?` 有版本。
3. 按需要设置：`AT+BPS=115200,0,1`（或 9600）、`AT+NAM=${名称}`、`AT+ULEN=16`、低功耗用 `AT+LPM`/`AT+PCT`。
4. 把 `AT+MAC?` 读到的地址写入服务端设备档案 `bleModuleAddress`。
5. 手机近场页点探活 → 读参数 → 写参数 → 复读确认。

**旧设备（DX-BT24）**

- 现场旧设备不动（旧固件 + 9600 + 私有密码），由 App 的自动发现 + 密码兜底继续支持。
- 若要把旧设备刷成新固件：先用 AT 控制台把 BT24 波特率设为 115200（BT24 支持到 115200），再刷固件，否则串口参数不匹配会无数据。

## 十、假设与前提

1. 型号为 **VG6328A-Pro**（BLE 从机 + SPP；不含 BLE 主机模式，主机模式需 VG6328A-Plus）。若实际用的是 Plus/-MS，AT 指令与 UUID 一致，仅多出主机相关条目。
2. 模组固件为《串口操作说明》对应的主线版本；若为 `atProtocol` 方言版，扩展测试工具候选表即可。
3. AT 命令与应答统一以 `\r\n\0` 结尾；读操作固定 `AT+CMD?`；成功 `+OK`、失败 `+ERP`。
4. App 侧按特征属性自动发现后，两代模组可共用一份客户端；服务 UUID 两代都是 `FFE0`。
5. 线帧 ≤19 B 远低于模组分包上限（APP ≤4096 B / 串口 ≤255 B），无需为分包做额外改动。
6. 硬件转接由硬件侧负责，当前 3.3 V 电平与交叉接线无需改动。
