# 2026-11-11 工作日志

## 生成 `docs/Eeprom_Wpara_explained.md`

按用户要求为 `Eeprom_Wpara()`（`qibiji/HARDWARE/REG/reg.c:203-225`）生成说明文档，未改动任何 `.c` / `.h` 源码。

文档结构沿用既有四份 `docs/*_explained.md` 的风格（一句话总览 → 业务定位 → 调用上下文 → 状态量 → 逐行解读 → 触发链 → 地址闭环 → 分工对比 → 时序 → 代码审查发现 → 易混点 → 出处对照），共 12 节 + 附录。

核实得到的关键结论（供后续问答复用）：

- **定位**：运行中闸门参数的「延迟落盘信箱」。TIM2 中断只置 `Witeflag` + `EepromAddr`，主循环 `main.c:82` 每轮取走即清。原因是 EEPROM 每字节死等 10ms、有擦写寿命，不能在 5ms 中断里写。
- **`EepromAddr` 不是 EEPROM 字节地址**，是命令码／`eeprom_buf[]` 字索引：`case 0x0004` → 写 `0x0008`（gate_maxturns）、`case 0x0005` → `0x000A`（gate_kaidu）、`case 0x0006` → `0x000C`（gate_kaidu_count），规律为「目标字节地址 = 命令码 × 2」，与 `reg.h:79-84` 的 `*_WORD_IDX` 注释吻合。数值与 `0x0004` 堵转阈值、`0x0006` 最大高度的真实地址撞车，极易误读（即 Lcd 文档里说的「同名异物」）。
- **`case 0x0005` 是死分支**：全库 Grep 确认 `EepromAddr` 只有 `reg.c:15` 初值 0、`switch.c:169`(0x0006)、`switch.c:202`(0x0004) 三处赋值，无人置 0x0005。且不影响功能，因为 `eepromToPara()` L134 用 `gate_kaidu_count*100/gate_maxturns` 重算开度覆盖了读回值。
- **两条触发链**：A = `Dispaly.c:562 autoFlag=1` → `dcmotor_auto()` → `JudeDir()` 每 5ms 检测到上限位（`switch.c:197-203`）→ 写全行程圈数；B = `JudeKaidu()` 每 500ms 要求「停机 + 连续两次采样 Num_count 不变」的双稳态确认（`switch.c:138-173`）→ 写断电位置。
- **四条落盘入口分工**：`paraToEeprom()`（首次播种）、`setpage()`（LCD 直接写 0x0004/0x0006）、`Config_WriteWordWithVerify()`（云端，带读回回滚）、`Eeprom_Wpara()`（0x0008/0x000C）。地址不重叠。
- **静态问题**：`Witeflag`/`EepromAddr` 缺 `volatile`（中断写、主循环读）；单槽信箱会覆盖丢请求；`switch.c` 先置标志后设命令码放大竞态；清标志早于写入且无重试、无写后校验；函数声明错放在 `24cxx.h:36`；`Witeflag` 拼写；`switch.c:200` 中断里 `printf`。

同日前序问答（未落盘，仅对话）：解释了 `AT24CXX_WriteWord` / `AT24CXX_WriteOneByte`（I2C 单字节事务、10ms tWR、`IWDG_Feed`、小端字节序与 `temp_l`/`temp_h` 命名反了、两笔事务的撕写窗口、主工程 ACK 返回值全丢弃而 init/boot 分支已改进）。

## 生成 `docs/ViewPages_explained.md`

用户说「生成 viewPage() 相关函数的文件」，实际工程里没有 `viewPage()`：`ViewPage` 是 `Display.h:5` 的宏常量 0，真正干活的是 `ViewPages()`（`Dispaly.c:346`）和 `DisplayViewPages()`（`Dispaly.c:394`）。已按此澄清并生成第 6 份 `docs/*_explained.md`，未改动任何 `.c` / `.h`。

关键结论（供后续复用）：

- **定位**：`ViewPages()` 是 LCD 页面调度员（改 `ViewNum` → 调分发器 → 同步 `PageSta`），不写屏、不决定刷新时机、不碰参数。`LcdDisplay()` 用四个触发源（切页 / 有按键 / 数据变化 / 500ms 兜底）门控它。
- **`page_last` 慢一拍是设计而非 bug**：`LcdDisplay()` L341 在 `ViewPages()` 返回后才写 `displayCache.page_last`，所以页面函数执行时看到的是上一轮页号；五个页面函数靠 `page_init_flag==0 || page_last != N` 实现「静态只画一次、动态每次刷」。
- **导航状态机**：`ViewNum` 0~4（`View_Num=4`），LEFT/RIGHT 双向环绕，`KEY_ENTER` 在 `ViewNum != 1` 时回首页——设置页特意豁免，把 ENTER 让给 `setpage()` 编辑用。`return ViewPage` 恒 0 且无人消费。
- **一键三方消费**：`KeyNum` 由 `KEY_Process()` 每轮覆盖（一次性事件），同轮依次被 `dcmotor_keycheck()` → `LcdDisplay()` → `ViewPages()`/`setpage()` 读。靠 `PageSta` 闸门 + 翻页键与电机键键值不重叠来避免冲突，代价是一拍延迟（无害）。显示模块还向电机模块导出 `autoFlag`。
- **`DisplayViewPages()` case 0/2/3 后面三条 `WRGDRAM128X8(...,0x00)`** 是擦除设置页残留的选中反白；case 4 自己用局部反白故不清。L403-417 三组 `SetPageNum=0/setParaflag=0` 被注释，重置责任转移到 `setpage()` L480-498。
- **`setpage()` 编辑链**：浏览态首次 ENTER 只选中（`0xff→0`）、第二次才进编辑；UP/DOWN 改 ASCII `Num`，ENTER 逐位确认，cnt 满退出落盘。堵转项 `cnt==8` 跳过小数点位，`asciitoInt(...)*100` 把屏显 A 换成 mA。闪烁由 500ms 兜底刷新驱动 `flag` 翻转，两次刷新 = 1Hz。
- **与 EEPROM 撞车（重要）**：`setpage()` L531/L550 的 `AT24CXX_WriteWord(0x0006/0x0004, ...)` 是**真实字节地址**；`EepromAddr=0x0004/0x0006` 是**命令码**（写到 0x0008/0x000C）。四个数值两两相同、语义不同，已在文档 §10 列对照表。现场按键这条直接同步写、无读回回滚（云端那条才有 `Config_WriteWordWithVerify`）。
- **静态问题 12 条**，较重要：五个旧宏 `SetPage/SetPara/SetVal/SetParaN/Home_Num` 全无引用；`HomeNum` 只写不读；500ms 兜底冲掉事件驱动优化但又是光标闪烁唯一驱动；`BLight_Ctrl` 三处注释对 `BackLight=1` 的极性互相矛盾，注释写 60s 实为 `100×300ms=30s` 且没有回首页代码；`Devicepage()` 动态部分全注释却仍监测 `PV_last`（空转）；`positionState` 三态映射重复写两遍；boot 工程同名 `DisplayViewPages` 是 2 字节 UNUSED 空函数。

同日前序问答（未落盘，仅对话）：解释了 `Num_count*100/gate_maxturns` 为何乘 100（0~1 比例 → 0~100 百分比量纲，C 整数除法必须先乘后除；`dc_motor.c:313/315` 全关写 0、全开写 100 是铁证）；系统解释了 `switch.c` 六个函数（位置测量层：JTAG Remap 释放 PB3/PB4、`JudeCount` 边沿检测 `cnt` 是摆设、`ChangeReality` 只置标志、`JudeDir` 到端点重设基准、`JudeKaidu` 双稳态确认、`JudeLocked` 空壳且堵转已迁到 ADC 电流判定）。
