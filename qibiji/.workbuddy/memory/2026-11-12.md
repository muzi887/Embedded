## 同日问答结论（可复用）

- `GenerateProgressBar1` 里「8 段」与「5 段」是两个层面：**8 段**是 GDRAM 物理存储/写屏格（16 点 = 2 字节，`x/16` 得段号 0~7，L471 / L501 硬编码 `i<8`，缓冲 `xianshi[16]`）；**5 段**是 `all=5` 的业务逻辑页份（L391–L400，`128/all≈25.6` 点）。以后分别称「物理格」和「逻辑份」，不要都用「段」。
- 因 25.6 > 16，每个逻辑份必然跨 2~3 个物理格 ⇒ L427「同段分支」恒不成立、是死代码；该分支自身还有 `0xFF >> 8 = 0` 的 bug，只有 `all≥8`（每份 ≤16 点）才可能触发。
- 换算桥梁：`x/16` → 物理段号，`x%16` → 段内第几点，再 `/8` 分低/高字节；L452–L493 跨段分支就是「起始格填尾 + 中间格 0xFF + 结束格填头」。

## 同日调研：项目里 Modbus 是怎么被使用的（纯解释，未生成文档）

- 结论：MCU 是 **Modbus RTU 主站**，走 RS485-1 = UART4（9600 8N1，DMA2_Ch3 + IDLE，缓冲 `DMA_Rece_Buf4[256]`），U7 MAX3485ESA、PD6(U4CE) 方向控制。每秒由 TIM2 `flag1s` 触发，主循环末尾 `manage485()` 发 `Rs485_Tx_data(0x01, 0x04, 0x3033, 0x0020)` → 8 字节 0x04 读输入寄存器请求（从站 0x01，起始 0x3033，读 32 个），原本要读太阳能/电池管理板数据写进 `armReg`。
- **关键：`485.c` 的 `Rs485_Rx_Data()` 只做 CRC 比对，解析赋值（bat_state / temperature / bat_cap / bat_vol / bat_curr / solar_vol / solar_curr）全被注释** ⇒ Modbus 目前「只问不用」，不参与闸门控制、不上云；应答唯一去处是 `UART4_IRQHandler()` 里 `Usart1_Send()` 转发到 PC 调试口。
- **两套实现只有一套活着**：`HARDWARE/485/485.c` + `HARDWARE/CRC16/crc16.c` 编进工程（uvprojx L519/524、QIBIJI.map 有 `485.o`/`crc16.o`、`main.o → manage485`）；`HARDWARE/MODBUS/modbus.c` **未编进工程**（map 无 `modbus.o`），但 IncludePath 仍含该目录（uvprojx L339），其 `modbus.h` 声明的 `Modbus_03/06/10_Slave` 全项目无定义，是早期网关版（三串口透传 + `sq` 环形队列 + `resend` 4s/10s）残留；它重复定义 `crc16()` 却无链接冲突，正是没参与编译的旁证。
- **CRC 字节序实算验证（订正此前误判）**：用 `crc16.c` 两张表对 `01 04 30 33 00 20` 实算，项目 `crc16()` 返回 `0x0EDD`；按 `crc>>8` 先发 `0E`、再发 `DD`，完整请求帧 `01 04 30 33 00 20 0E DD`。标准 Modbus CRC（多项式 0xA001）参考值 `0xDD0E`，规范「低字节先发」即线上 `0E DD` —— **两者完全一致，项目符合标准 RTU，并未反**。只是 `crc16()` 返回值的 16 位表示与常见 `0xDD0E` 写法互为字节交换；`crc16.c:4`「低位在前」与 `modbus.c:13`「高字节在前」看似矛盾，实为同一线上顺序的两种描述。接收侧 `CharToInt` 按 `(b0<<8)|b1` 解释同理自洽。
- `0x3033` + 32 个寄存器与注释右侧 `33/36/45/46/47/4E/4F` 完全对上：第 N 个寄存器地址 = `0x3033+(N-1)`，推得 bat_state=0x3033、temperature=0x3036、bat_cap=0x3045、bat_vol=0x3046、bat_curr=0x3047、solar_vol=0x304E、solar_curr=0x304F；字段号 10~16 与 `reg.h:31-37` 一致。应答 `01 04 40` + 64 字节 + CRC = 69 字节，数据从 `rs485_rx_buf[3]` 起。
- 静态问题：`rs485_rx_buf[100]` 对 256 字节 DMA 无边界检查；`len<2` 时 `len-2` 下溢；`manage485()` 发请求前清 `Usart4_Rec_Cnt` 会抹掉刚到的应答；IDLE 中断里 `Usart1_Send` 逐字节轮询 TC 拖长中断；无超时重试（旧 `resend` 未编译）；`dc_motor.c:362` 注释「flag1s 由 485 设置」写反（TIM2 置位、485 清零）；`Rs485_Tx_data` 第 5 参数名 `val` 实为寄存器数量。
- 出处：`qibiji/HARDWARE/485/485.c` · `HARDWARE/CRC16/crc16.c` · `HARDWARE/MODBUS/modbus.c/.h` · `HARDWARE/USART/usart4.c` · `USER/main.c:32-36, 83` · `HARDWARE/TIMER/timer.c:245-246` · `USER/QIBIJI.map` · `hard/hardware_report_assets/元件-网络明细.csv:258-259`（U7 MAX3485、U5 CN3767 太阳能充电、pin87 U4CE）。
