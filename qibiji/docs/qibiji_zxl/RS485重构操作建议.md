# RS485 通讯模块重构操作建议（qibiji_zxl）

> **起点**：`qibiji_zxl` 现在有 KEY / TIM3 / DEBUG_UART / LCD / ADC / DCMOTOR / GATEIO 几个模块，`main.c` 跑轮询 + 显示 + 电机。没有 `HARDWARE/RS485/`，没有 4G / GPRS，没有 `armReg` 这套全局寄存器，也没有 TIM2 的 `flag1s`。
>
> **目标**：把原工程 `qibiji/HARDWARE/485/485.c`（查询调度 + 应答解析）、`qibiji/HARDWARE/USART/usart4.c`（UART4 + DMA + IDLE）、`qibiji/HARDWARE/CRC16/crc16.c`（CRC 查表）三处拼起来，做成一个独立模块 `HARDWARE/RS485/rs485.c/.h`：**每 1 秒通过 UART4 发一帧 Modbus 读寄存器请求，收到应答后校验 CRC 并解析出 7 个电池/太阳能数据**，对外只给只读 getter。不依赖 `armReg`、不依赖 GPRS。
>
> **怎么用这份文件**：第 1、2 节先讲这块链路在系统里干什么、原工程现状（很短，务必先看）；第 3～5 节是引脚、时基、帧格式与 CRC 这些必须先懂的事实；第 6、7 节是两个新文件的完整代码（可直接拷，CRC 表逐字给全）；第 8 节改 `main.c`；第 9 节改 Keil 工程；第 10 节是机制讲解；第 11 节是验证记录（本轮已做 host 桩验证，26 项断言全过）；第 12 节是与原工程对照、约束和待办。
>
> **实施顺序**：本模块独立，放在 `DCMOTOR` 之后做即可。它和电机/继电器唯一的交界是 PD6——**PD6 是 RS485 的方向脚，不归继电器**，边界见《DCMotor重构操作建议.md》§16。本轮不改 LCD 显示内容，解析出来的值先用 getter 放着，接到屏幕是后续"真数据接线"的独立需求。

## 1. 这块链路在系统里干什么（先看这个）

一句话：**它是控制器向"电池/太阳能数据采集板"要数据的通道。**

打个比方：控制器是"问询方"，采集板是"被问的仪表"。控制器每秒钟喊一嗓子——"把 0x3033 开始的 32 个寄存器报给我"（这就是那帧 `01 04 30 33 00 20 ...`）；采集板回一帧 69 字节，里面装着电池状态、温度、容量、电压、电流、太阳能电压、电流这 7 个数。控制器把回包校验一下、拆出这 7 个数，供别处读。

对应到系统里的位置：

| 步骤 | 谁做 | 在哪 |
|---|---|---|
| ① 每秒发一帧查询 | 本模块 `RS485_Tick()` 计数到 100 拍 | `rs485.c`（本轮新建） |
| ② 把帧真正送出 UART4、切收发方向 | `s_SendQuery()` 操作 PD6 + USART4 | `rs485.c` |
| ③ 收完整帧 | UART4 空闲中断 + DMA2_CH3 搬字节 | `RS485_UART4_IRQHandler()`（在 `rs485.c` 里） |
| ④ 校验 CRC、拆 7 个字段 | 主循环调 `RS485_PollRx()` | `rs485.c` |
| ⑤ 别人来读这 7 个数 | getter | `rs485.h` |

**它测的量代表什么**：7 个字段都是采集板寄存器里的原始值（raw），**缩放单位留给读的人**（LCD 或以后上报）。本模块不做"×0.1 变成伏特"这种事——职责就是忠实搬数。

## 2. 原工程现状：一个"只问不用"的主站

理解原工程，是这份重构的关键前提。三处代码串起来看：

**① 调度（`485.c` manage485）**：靠 TIM2 的 `flag1s`，每秒把接收计数清 0、发一帧查询 `Rs485_Tx_data(0x01,0x04,0x30,0x33,0x20)`，然后调 `Rs485_Rx_Data()`。

**② 发送（`Rs485_Tx_data`）**：拼 8 字节 `地址 功能 起始地址高 起始地址低 数量高 数量低 CRC高 CRC低`，CRC 用 `crc16()` 查表算。

**③ 接收（`Rs485_Rx_Data`）**：把 DMA 缓冲搬到局部数组 → CRC 校验 → **下面 7 个字段的解析整段被 `//` 注释掉了**：

```c
//  crc = crc16(rs485_rx_buf, len - 2);
//  if (crc != CharToInt(&rs485_rx_buf[len - 2])) { return; }
//
//  val_h = rs485_rx_buf[3];  val_l = rs485_rx_buf[4];
//  armReg.bat_state = (val_h << 8) | val_l;      // 13 电池状态 reg 33
//  ... 温度/容量/电压/电流/太阳能电压/电流 全部注释
```

也就是说：**原工程只会问、不做任何解析，收到的数据连 CRC 校验都被跳过**（校验那段也在注释块里）。此前的结论——"对外唯一在跑的协议链路是 4G 模块内 MQTT + 私有 JSON；RS485 是只问不用；`HARDWARE/MODBUS/` 没编进工程；SL651 没用"——与本轮源码探查一致。

**本轮重构做了原工程没做完的那半截**：把 CRC 校验和 7 字段解析真正实现出来，并用 host 桩验证到能正确解出数据。这不是"照搬"，是"接着写完"。

**明确不搬**：

| 项 | 为什么不搬 |
|---|---|
| `armReg` / `reg.c` 全局寄存器 | 新工程没有这套结构；本模块用自己的 `static` 变量存 7 个值，对外 getter 读。原工程写到 `armReg.bat_state` 的那些行全是注释，本来也没生效 |
| `Rs485_Rx_Data()` 里转发给 GPRS（`Usart1_Send`） | 新工程没有 GPRS；原工程是在 UART4 的 IDLE 中断里把原始帧转给串口 1 的。本模块不转发 |
| `HARDWARE/MODBUS/modbus.c` | 未编进工程（Keil 工程里无该文件节点），是另一套未完成的 Modbus 实现，不碰 |
| SL651 规约 | 本工程零实现，不碰 |
| TIM2 的 `flag1s` | 新工程只有 TIM3 的 10ms 节拍；本模块内部对 10ms 计数派生 1s 查询节拍和 3s 超时，不动 `timer.c` |

## 3. 引脚与硬件边界

| 引脚 | 方向 | 用途 | 归属模块 |
|---|---|---|---|
| **PC10** | 输出（AF_PP） | UART4_TX，向采集板发查询帧 | RS485（本模块） |
| **PC11** | 输入（浮空） | UART4_RX，收应答帧 | RS485（本模块） |
| **PD4** | 输出（推挽，初值 1） | 485 侧第一路限位控制输出，宏名 `V01_CTRL` | RS485（本模块） |
| **PD5** | 输出（推挽，初值 1） | 485 侧第二路限位控制输出，宏名 `V02_CTRL` | RS485（本模块） |
| **PD6** | 输出（推挽） | RS485 收发方向：高=发送、低=接收 | RS485（本模块） |

**边界要特别强调**：PD6 是 RS485 收发方向脚，**不是继电器**；PD4/PD5 是 485 这一路的限位控制输出（`V01_CTRL` / `V02_CTRL`），原先误放在 DCMOTOR 里，现已划归本模块。电机那边只剩 PD1（主电）、PD3（方向）两个继电器脚。四者都在 GPIOD，但职责不同——别把 PD1/PD3 塞进 RS485，也别把 PD4/PD5/PD6 塞回 DCMOTOR。

硬件上 RS485 是半双工：同一对 A/B 线既发又收，靠 PD6 切换收发器方向。所以发帧前要把 PD6 拉高、发完立即拉回低（否则会挡住应答）。这一点和原工程 `Usart4_Send()` 里的 `RS485_CE4_H` / `RS485_CE4_L` 是一回事。

## 4. 时基：从 `flag1s` 到 10ms 节拍派生

原工程靠 TIM2 每秒置一次 `flag1s` 驱动查询。新工程没有 TIM2，只有 TIM3 的 `Tick_10ms_Take()`（消费式，取走即清）。

本模块自己派生两个计数器（都在 `RS485_Tick()` 里，每 10ms 调一次）：

- `s_tick_cnt`：数到 100（=1s）发一帧查询，然后清 0；
- `s_no_reply_ticks`：只有在"数据有效"时才累加，数到 300（=3s）没有新的有效应答，就把数据置为无效（防止采集板掉线后一直显示旧值）。

**关键点**：`RS485_Tick()` 必须和 `KEY_Tick()` / `ADC_Tick()` / `DCMOTOR_Tick()` 挂在**同一个** `if (Tick_10ms_Take())` 里，共用一拍。`Tick_10ms_Take()` 是消费式的，写成两个独立 `if`，第二个几乎永远取不到。

```
if (Tick_10ms_Take())
{
    KEY_Tick();
    LCD_BACKLIGHT_Tick();
    ADC_Tick();
    DCMOTOR_Tick();
    RS485_Tick();        /* 本轮新增 */
}
```

`RS485_PollRx()` 则放在主循环里每轮调用（它只在 ISR 标记了"收到完整帧"时才干活）。

## 5. 帧格式与 CRC（本轮最容易踩坑的一节）

### 5.1 查询帧（8 字节）

```
地址  功能  起始地址高  起始地址低  数量高  数量低  CRC高  CRC低
01    04    30          33          00      20      0E      DD
```

- `01` 从站地址；`04` 功能码"读输入寄存器"；
- `30 33` 起始寄存器地址 0x3033；`00 20` 读 32 个寄存器；
- 最后两字节是 CRC：**线上顺序是 `0E DD`**。

### 5.2 应答帧（69 字节）

```
地址(1) 功能(1) 字节数(1) 数据(32×2=64) CRC(2)
01      04      40        ...            CRC高 CRC低
```

数据区从 `buf[3]` 开始（前面是地址、功能、字节数）。7 个字段在数据区的偏移（照抄原工程注释里的索引，注意这是**整帧下标**）：

| 字段 | 整帧下标 | 寄存器 | getter |
|---|---|---|---|
| 电池状态 bat_state | buf[3], buf[4] | 0x3033 | `RS485_GetBatState()` |
| 环境温度 temperature | buf[9], buf[10] | 0x3036 | `RS485_GetTemperature()` |
| 电池容量 bat_cap | buf[39], buf[40] | 0x3045 | `RS485_GetBatCap()` |
| 电池电压 bat_vol | buf[41], buf[42] | 0x3046 | `RS485_GetBatVol()` |
| 电池电流 bat_curr | buf[43], buf[44] | 0x3047 | `RS485_GetBatCurr()` |
| 太阳能电压 solar_vol | buf[57], buf[58] | 0x304E | `RS485_GetSolarVol()` |
| 太阳能电流 solar_curr | buf[59], buf[60] | 0x304F | `RS485_GetSolarCurr()` |

每个值都是**大端**：`(buf[i] << 8) | buf[i+1]`。

### 5.3 CRC：为什么不能换成教科书位算法（重要）

原工程 `crc16()` 是 Modbus CRC-16 的**查表法**，返回的是 `((hi<<8)|lo)` 形式。对查询帧 `01 04 30 33 00 20`：

- 原工程查表法返回 **`0x0EDD`**；
- 教科书按位算法（多项式 0xA001）返回 **`0xDD0E`**——正好字节交换；
- 两者发出的**线上字节一样都是 `0E DD`**，因为发送函数写的是 `buf[6]=crc>>8; buf[7]=crc`（先发高字节），而查表法把低字节 `0x0E` 放在了高 8 位。

**坑就在这里**：如果你把查表法换成教科书位算法、却保留"先发高字节"的写法，线上会变成 `DD 0E`（错）；应答校验时同理，比较字节序会全对不上。**所以本模块坚持逐字使用原工程的查表法和表**，不做替换。

救命提醒：**CRC 表必须从原工程 `crc16.c` 逐字复制，一个字节都不能错**。本轮验证时就踩过一次——复制时高位表 `s_crc_hi[80..87]` 这 8 个字节错了（写成 `01 C0 80 41 00 C1 81 40`，正确应是 `00 C1 81 40 01 C0 80 41`）。后果很隐蔽：

- 6 字节查询帧的 CRC 计算**碰不到**索引 80~87，所以查询帧线上一直是正确的 `0E DD`，看起来一切正常；
- 但 67 字节的应答帧会用到这段表，CRC 校验必然失败，7 个字段一个都解不出来。

第 7 节给出的表是从原工程权威文件逐字导出、并已逐字节比对过的正确版本，**直接用它，不要自己重敲**。校验方法见第 11 节。

## 6. 第 1 步：新建 `HARDWARE/RS485/rs485.h`

新目录 `qibiji_zxl/HARDWARE/RS485/` 需要你手动建（Keil 里新建文件夹并加进工程）。先放头文件：

```c
#ifndef __RS485_H
#define __RS485_H

#include "sys.h"

/* ---------------------------------------------------------------------------
 * RS485 / Modbus-RTU master (UART4: PC10=TX, PC11=RX, PD6=direction)
 *
 * Polls one battery-data register block once per second:
 *   request : 01 04 30 33 00 20 CRC   (8 bytes, wire CRC = 0E DD)
 *   reply   : 01 04 <bytecount> <data...> CRC
 *
 * Seven fields are extracted from the reply data area and exposed via getters.
 * No armReg / GPRS dependency: the module keeps its own latest values.
 *
 * Constraints: C90, ASCII-only comments/strings.
 * --------------------------------------------------------------------------- */

/* ---------------- 485-side limit control outputs: PD4 / PD5 ----------------
 * Bit-band (bit-band alias) macros: writing 1/0 touches only this bit, with
 * no read-modify-write of the whole ODR. They belong to the 485-side limit
 * control, NOT to the motor module (moved out of DCMOTOR when it was split).
 * Both are configured as push-pull outputs and set to 1 (inactive) by
 * RS485_Init(), which took over the old DCMOTOR_RelayInit() job.
 */
#define V01_CTRL   PDout(4)   /* PD4: limit control output #1 */
#define V02_CTRL   PDout(5)   /* PD5: limit control output #2 */

/* data validity: set after first CRC-OK reply, cleared after 3s no reply */
uint8_t RS485_DataValid(void);

/* decoded values (raw register values, scaling is left to the caller/LCD) */
uint16_t RS485_GetBatState(void);     /* reg 0x3033 */
uint16_t RS485_GetTemperature(void);  /* reg 0x3036 */
uint16_t RS485_GetBatCap(void);       /* reg 0x3045 */
uint16_t RS485_GetBatVol(void);       /* reg 0x3046 */
uint16_t RS485_GetBatCurr(void);      /* reg 0x3047 */
uint16_t RS485_GetSolarVol(void);     /* reg 0x304E */
uint16_t RS485_GetSolarCurr(void);    /* reg 0x304F */

/* diagnostics */
uint16_t RS485_GetGoodFrames(void);   /* number of CRC-OK replies */
uint16_t RS485_GetBadFrames(void);    /* number of CRC-fail / bad replies */

/* lifecycle */
void RS485_Init(void);                /* UART4 + DMA2_CH3 + IDLE IRQ + NVIC; call once */
void RS485_Tick(void);                /* call on the 10ms system tick */
void RS485_PollRx(void);              /* call in main loop: CRC-check + decode a flagged frame */
void RS485_UART4_IRQHandler(void);    /* UART4 idle ISR, must live in rs485.c */

#endif
```

**PD4/PD5 的初始化职责**：原 `DCMOTOR_RelayInit()` 顺手把 PD4/PD5 配成推挽输出并置 1，宏和这段初始化已一起从电机侧删除。现在统一由 `RS485_Init()` 负责（见 §7）：先写 `V01_CTRL = 1` / `V02_CTRL = 1`，再把 PD4/PD5 配成 `GPIO_Mode_Out_PP`，保证上电瞬间输出就是"不动作"的高电平，不会因为模式切换顺序产生低电平毛刺。GPIOD 的时钟 `RS485_Init()` 里本来就为 PD6 开了，不用重复开。

**关于 `RS485_UART4_IRQHandler()` 放在哪**：和 TIM3 的 `TIM3_IRQHandler` 写在 `timer.c` 里一样，中断函数放在模块自己的 `.c` 里，这样接收缓冲 `s_rx_buf` 可以保持私有、不用 `extern` 出去。`startup_stm32f10x_hd.s` 里的中断向量名字 `UART4_IRQHandler` 不用改（链接器按这个名字找），只要 `.c` 里定义的是这个名字即可。

#define RX_BUF_LEN       128u   /* reply is 3 + 64 + 2 = 69 bytes; 128 leaves margin */
#define POLL_TICKS       100u   /* 100 x 10ms = 1s between queries */
#define RX_TIMEOUT_TICKS 300u   /* 3s with no valid reply -> data invalid */
#define REPLY_MIN_LEN    69u    /* addr+cmd+count + 32regs*2 + crc2 */

/* RS485 direction control (PD6): high = transmit, low = receive */
#define RS485_TX_EN()   (PDout(6) = 1u)
#define RS485_RX_EN()   (PDout(6) = 0u)

static u8  s_rx_buf[RX_BUF_LEN];
static volatile u16 s_rx_len;     /* set by ISR, consumed by main loop */

static u16 s_tick_cnt;            /* 10ms ticks since last query */
static u16 s_no_reply_ticks;      /* 10ms ticks since last CRC-OK reply */
static u8  s_valid;

static u16 s_bat_state;
static u16 s_temperature;
static u16 s_bat_cap;
static u16 s_bat_vol;
static u16 s_bat_curr;
static u16 s_solar_vol;
static u16 s_solar_curr;

static u16 s_good_frames;
static u16 s_bad_frames;

/* CRC (original byte order: value stores lo byte in the low 8 bits). */
static u16 s_Crc16(const u8 *buf, u16 len)
{
    u8 hi = 0xFFu;
    u8 lo = 0xFFu;
    u16 i;
    u8 idx;
    while (len--)
    {
        idx = (u8)(hi ^ *buf++);
        hi = (u8)(lo ^ s_crc_hi[idx]);
        lo = s_crc_lo[idx];
    }
    return (u16)(((u16)hi << 8) | lo);
}

/* assemble trailing bytes exactly like the original wire format */
static void s_AppendCrc(u8 *buf, u16 len)
{
    u16 crc = s_Crc16(buf, len);
    buf[len]     = (u8)(crc >> 8);   /* high byte first on the wire */
    buf[len + 1] = (u8)crc;          /* low byte */
}

static void s_SendQuery(void)
{
    u8 req[8];
    u16 i;
    req[0] = 0x01u;      /* slave address */
    req[1] = 0x04u;      /* function: read input registers */
    req[2] = 0x30u;      /* start address high */
    req[3] = 0x33u;      /* start address low */
    req[4] = 0x00u;      /* quantity high */
    req[5] = 0x20u;      /* quantity low: 32 registers */
    s_AppendCrc(req, 6u);

    RS485_TX_EN();
    for (;;) { if (USART_GetFlagStatus(UART4, USART_FLAG_TC) != RESET) break; }
    for (i = 0u; i < 8u; i++)
    {
        USART_SendData(UART4, req[i]);
        while (USART_GetFlagStatus(UART4, USART_FLAG_TC) == RESET) { }
    }
    while (USART_GetFlagStatus(UART4, USART_FLAG_TC) == RESET) { }
    RS485_RX_EN();
}

/* big-endian value from two data bytes */
static u16 s_Word(const u8 *p)
{
    return (u16)(((u16)p[0] << 8) | p[1]);
}

/* parse a CRC-checked reply. Data area starts at buf[3] (addr,cmd,count). */
static void s_ParseReply(const u8 *buf, u16 len)
{
    if (len < REPLY_MIN_LEN) { s_bad_frames++; return; }
    if (buf[0] != 0x01u) { s_bad_frames++; return; }
    if (buf[1] != 0x04u) { s_bad_frames++; return; }

    s_bat_state   = s_Word(&buf[3]);
    s_temperature = s_Word(&buf[9]);
    s_bat_cap     = s_Word(&buf[39]);
    s_bat_vol     = s_Word(&buf[41]);
    s_bat_curr    = s_Word(&buf[43]);
    s_solar_vol   = s_Word(&buf[57]);
    s_solar_curr  = s_Word(&buf[59]);

    s_valid = 1u;
    s_no_reply_ticks = 0u;
    s_good_frames++;
}

/* Called from main loop when ISR flagged a complete frame. */
void RS485_PollRx(void)
{
    u16 len;
    u16 crc_calc;
    u16 crc_rx;

    if (s_rx_len == 0u) return;

    len = s_rx_len;
    s_rx_len = 0u;                 /* release buffer for next frame */

    if (len < 4u) { s_bad_frames++; return; }

    /* trailing two bytes on wire are CRC high, CRC low; original compares
     * them via CharToInt => (byte[len-2]<<8)|byte[len-1]. */
    crc_calc = s_Crc16(s_rx_buf, (u16)(len - 2u));
    crc_rx = (u16)(((u16)s_rx_buf[len - 2u] << 8) | s_rx_buf[len - 1u]);
    if (crc_calc != crc_rx) { s_bad_frames++; return; }

    s_ParseReply(s_rx_buf, len);
}

void RS485_Init(void)
{
    GPIO_InitTypeDef gpio;
    USART_InitTypeDef usart;
    DMA_InitTypeDef dma;
    NVIC_InitTypeDef nvic;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC | RCC_APB2Periph_GPIOD, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_UART4, ENABLE);
    RCC_AHBPeriphClockCmd(RCC_AHBPeriph_DMA2, ENABLE);

    /* PD6: direction control, start in receive mode */
    gpio.GPIO_Pin = GPIO_Pin_6;
    gpio.GPIO_Mode = GPIO_Mode_Out_PP;
    gpio.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOD, &gpio);
    RS485_RX_EN();

    /* PD4/PD5: 485-side limit control outputs, idle high (inactive).
     * Job taken over from the removed DCMOTOR_RelayInit(): set ODR bits
     * first, then switch the pins to output, so there is no low glitch. */
    V01_CTRL = 1u;
    V02_CTRL = 1u;
    gpio.GPIO_Pin = GPIO_Pin_4 | GPIO_Pin_5;
    gpio.GPIO_Mode = GPIO_Mode_Out_PP;
    gpio.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOD, &gpio);

    /* PC10 = TX (AF push-pull), PC11 = RX (floating input) */
    gpio.GPIO_Pin = GPIO_Pin_10;
    gpio.GPIO_Mode = GPIO_Mode_AF_PP;
    gpio.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOC, &gpio);
    gpio.GPIO_Pin = GPIO_Pin_11;
    gpio.GPIO_Mode = GPIO_Mode_IN_FLOATING;
    GPIO_Init(GPIOC, &gpio);

    USART_DeInit(UART4);
    usart.USART_BaudRate = 9600u;
    usart.USART_WordLength = USART_WordLength_8b;
    usart.USART_StopBits = USART_StopBits_1;
    usart.USART_Parity = USART_Parity_No;
    usart.USART_HardwareFlowControl = USART_HardwareFlowControl_None;
    usart.USART_Mode = USART_Mode_Rx | USART_Mode_Tx;
    USART_Init(UART4, &usart);

    /* DMA2_Channel3 = UART4 RX (fixed by chip design) */
    DMA_DeInit(DMA2_Channel3);
    dma.DMA_PeripheralBaseAddr = (u32)&UART4->DR;
    dma.DMA_MemoryBaseAddr = (u32)s_rx_buf;
    dma.DMA_DIR = DMA_DIR_PeripheralSRC;
    dma.DMA_BufferSize = RX_BUF_LEN;
    dma.DMA_PeripheralInc = DMA_PeripheralInc_Disable;
    dma.DMA_MemoryInc = DMA_MemoryInc_Enable;
    dma.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Byte;
    dma.DMA_MemoryDataSize = DMA_MemoryDataSize_Byte;
    dma.DMA_Mode = DMA_Mode_Normal;
    dma.DMA_Priority = DMA_Priority_Medium;
    dma.DMA_M2M = DMA_M2M_Disable;
    DMA_Init(DMA2_Channel3, &dma);

    nvic.NVIC_IRQChannel = UART4_IRQn;
    nvic.NVIC_IRQChannelPreemptionPriority = 2u;  /* 按工程 NVIC 分组调整 */
    nvic.NVIC_IRQChannelSubPriority = 0u;
    nvic.NVIC_IRQChannelCmd = ENABLE;
    NVIC_Init(&nvic);

    USART_ITConfig(UART4, USART_IT_IDLE, ENABLE);
    USART_DMACmd(UART4, USART_DMAReq_Rx, ENABLE);
    DMA_Cmd(DMA2_Channel3, ENABLE);
    USART_Cmd(UART4, ENABLE);

    s_tick_cnt = 0u;
    s_no_reply_ticks = 0u;
    s_valid = 0u;
    s_rx_len = 0u;
    s_bat_state = 0u; s_temperature = 0u; s_bat_cap = 0u;
    s_bat_vol = 0u; s_bat_curr = 0u; s_solar_vol = 0u; s_solar_curr = 0u;
    s_good_frames = 0u; s_bad_frames = 0u;
}

void RS485_Tick(void)
{
    s_tick_cnt++;
    if (s_tick_cnt >= POLL_TICKS)
    {
        s_tick_cnt = 0u;
        s_SendQuery();
    }

    if (s_valid != 0u)
    {
        s_no_reply_ticks++;
        if (s_no_reply_ticks >= RX_TIMEOUT_TICKS)
            s_valid = 0u;   /* stale: no valid reply for 3s */
    }
}

/* UART4 idle interrupt: a complete frame has arrived. Read DR to clear IDLE,
 * snapshot DMA length, restart DMA. Kept here so the RX buffer stays private. */
void RS485_UART4_IRQHandler(void)
{
    u16 len;
    if (USART_GetITStatus(UART4, USART_IT_IDLE) != RESET)
    {
        (void)USART_ReceiveData(UART4);   /* read DR to clear IDLE flag */
        len = (u16)(RX_BUF_LEN - DMA_GetCurrDataCounter(DMA2_Channel3));
        if ((len > 0u) && (len <= RX_BUF_LEN))
            s_rx_len = len;              /* hand off to main loop */
        USART_ClearITPendingBit(UART4, USART_IT_IDLE);
        DMA_Cmd(DMA2_Channel3, DISABLE);
        DMA_SetCurrDataCounter(DMA2_Channel3, RX_BUF_LEN);
        DMA_Cmd(DMA2_Channel3, ENABLE);
    }
}

## 10. 机制讲解：一帧数据是怎么走完的

按"先问后收再解"的业务顺序串一遍，这也是排查问题时的顺序：

**① 发（每秒一次）**：`RS485_Tick()` 数到 100 拍 → `s_SendQuery()` 拼 8 字节请求、`s_AppendCrc()` 补上 CRC → 拉高 PD6 切到发送 → 逐字节送进 UART4、每字节等发送完成 → 最后拉低 PD6 切回接收。**发完必须切回接收**，否则采集板的应答进不来。

**② 收（中断里）**：一帧应答通过 DMA2_CH3 自动搬进 `s_rx_buf`；帧与帧之间有空闲，UART4 触发 IDLE 中断 → `RS485_UART4_IRQHandler()` 读 DR 清标志、用 `RX_BUF_LEN - DMA剩余计数` 算出这帧多少字节 → 记到 `s_rx_len` → 重启 DMA 准备下一帧。**中断里只记长度，不做解析**（解析放主循环，避免在中断里待太久）。

**③ 解（主循环）**：`RS485_PollRx()` 看到 `s_rx_len` 非 0 → 取出长度、立刻清 0（释放缓冲）→ 对前 `len-2` 字节算 CRC，和帧尾两字节比：`crc_calc = s_Crc16(buf, len-2)`，`crc_rx = (buf[len-2]<<8)|buf[len-1]`。不等就记一次 bad frame 丢掉；相等才 `s_ParseReply()`：查长度≥69、地址=1、功能=4，再按 §5.2 的下标拆 7 个字段，置 `s_valid=1`、超时计数清 0、good frame +1。

**④ 时效**：只要 `s_valid=1`，每次 `RS485_Tick()` 就给 `s_no_reply_ticks` 加 1；3 秒内没有新的有效帧就置回 0。这样采集板掉线或线断了，读数不会永远停在旧值——读之前先看 `RS485_DataValid()`。

**⑤ 读**：别处要用数据时调 7 个 getter，值是原始寄存器值，缩放留给调用方。
