# 远程下发重构操作建议（qibiji_zxl MCU 侧）

> **文档定位**：4G 平台参数下发链路的"管道"已通（收帧 → JSON 解析 → 分发 → 应答），本文只覆盖 **MCU 侧还缺的功能**：指令面扩充、参数落盘、OTA 开闸入口、request_reply 通用化。OTA 开闸部分与 `OTA重构操作建议.md` 阶段二联动，本文不重复 bootloader 侧内容。
> **现状基线**：2026-11-21，按当前代码逐项核实（行号以本工作区为准）。**未动任何代码**，所有改动等用户确认后实施。

---

## 一、下发链路现状（已实现部分，勿重复造）

一条下行指令从平台到执行的完整路径：

```
平台 JSON ──MQTT──► WH-LTE-7S1 透传 ──USART2+DMA──► uart_queue 收帧
──► GPRS_JSON_ParseProcess()（gprs_json.c:117）──► cJSON 解析
──► 分流：AT 回包 / 保活 ack / request_reply / service
──► serviceCode 分发（gprs_json.c:199-220）──► 动作函数 ──► GPRS_ReplyServices 应答
```

已支持的 3 个 serviceCode：

| serviceCode | 处理函数 | 行为要点 |
|---|---|---|
| `setValue` | `GPRS_SetValue()`（gprs_json.c:77） | 范围 [0,100] 检查 → 校准中拒绝（409）→ `DCMOTOR_SetTarget()`；应答先回，开度进度由属性上报跟进 |
| `stopGate` | `GPRS_StopGate()`（gprs_json.c:110） | `DCMOTOR_Request(MOTOR_STOP)` + 应答 |
| `ReSet` | gprs_json.c:212-218 | **先应答、后延迟复位**（`GPRS_Reset_Request()`）——这是"应答先行 + 动作延后"的现成模板 |

复用时直接抄的三个机制：

- **信封字段拷贝**：`id`/`type` 在 `cJSON_Delete` 前先拷进 `g_json_hdr`（gprs_json.c:173-181，valuestring 指针在删树后失效）；
- **应答**：`GPRS_ReplyServices()`（同步）/ `GPRS_ReplyServicesPush()`（带超时，gprs_json.h:18-20），自动带 `TOPIC_SERVICE_REPLY`（gprs_config.h:28）和回显的 `id`；
- **单帧失败不卡队列**：解析/校验失败 `continue` 不 `return`（gprs_json.c:169）。

## 二、缺口总览

| # | 缺口 | 性质 | 优先级 |
|---|---|---|---|
| 1 | 只读指令：`getFirmware` / `property_get` / `getConfig` | 纯增量，不动现有逻辑 | 高（最便宜，先做） |

## 三、阶段一：三个只读指令（每条 = 1 个分支 + 1 个组包函数）

### 1. `getFirmware` —— 版本查询

版本宏已有：`USER/app_info.h:4` `APP_FW_VERSION "V1.0.0"`（目前只有 LCD 在用，`lcd_pages.c:525`）。

**改动点**：gprs_json.c 分发段（201 行 `setValue` 分支之后）加：

```c
else if (strcmp(serviceCode->valuestring, "getFirmware") == 0)
{
    GPRS_ReplyServices(0, "success", "{\"version\": " APP_FW_VERSION "}");
}
```

注意 `APP_FW_VERSION` 是字符串字面量，可直接用编译期拼接；若嫌裸拼难读，就 `snprintf` 进 `s_json_buf` 再传。与 OTA 文档阶段三的联动：此接口回的是**编译期版本**，而 bootloader 向平台上报的是 **EEPROM OTA_ver**——版本号联动策略见 OTA 文档阶段三，两处必须统一口径，否则平台对比版本会失真。

### 2. `property_get` —— 平台主动读实时状态

快照构建函数已经存在：`PropertyReport_BuildSnapshot()`（`property_report.h:25`，属性上报模块在用它拼 JSON）。property_get 只是"被动触发一次同样的快照、装进应答"：

```c
else if (strcmp(serviceCode->valuestring, "property_get") == 0)
{
    char snap[UART_TX_JSON_LEN];
    if (PropertyReport_BuildSnapshot(snap, sizeof(snap)) != 0u)
        GPRS_ReplyServices(0, "success", snap);
    else
        GPRS_ReplyServices(500, "snapshot failed", "{}");
}
```

不需要动 `PropertyReport_Process()` 的定时逻辑，一个快照调用即可。

### 3. `getConfig` —— 平台读当前参数

依赖阶段二的参数表（见下），参数表定了之后本条是它的只读镜像：遍历参数表 → `snprintf` 拼一个 JSON 对象 → 应答。建议与阶段二同轮实现，避免先做空壳。

### 验证

平台侧各发一次三条指令，看串口 `[GPRS] TX` 应答帧：`getFirmware` 版本号与 `app_info.h` 一致；`property_get` 的开度值与 LCD 当前显示一致。

## 四、阶段二：`setConfig` 参数下发 + EEPROM 落盘（功能本体）

这是"参数下发"区别于"指令下发"的核心：`setValue` 是一次性动作，参数要**断电存活**。

### 4.1 先决策：允许远程改哪些参数

建议首批白名单收窄到 3 个（都是运行阈值、无校准耦合）：

| 参数 key | 现值来源 | 范围 |
|---|---|---|
| `stallMa` | `adc.c` 堵转电流阈值（默认 3500mA，`ADC_STALL_MA_DEFAULT`=adc.h:27，setter `ADC_SetStallThresholdMa()`=adc.c:349） | **与旧工程一致**（reg.c:108-122）：1000~0xFFFF。旧工程把 <1000 视为旧 0.1A 编码（×100 迁移为 mA），≥1000 才当合法 mA 值；上限未设 |
| `reportCycleMs` | `property_report.c` 上报周期 | 1s~60s |
| `railLow` | `adc.c` `ADC_RAIL_LOW` | 2~100 |

校准相关参数（`s_cal_*`、零点）**不进白名单**——远程改校准量风险太高，现场用按钮/产线工具做。

### 4.2 EEPROM 地址规划（先盘点再分配，不能跳过）

硬约束：**本板是 AT24C02，总共 256 字节**（`eeprom_drv.h:19-20`，`EE_ADDR=250` 是 Marker 标志字节）。已占用区间：

- **OTA 组 200~243**：bootloader 约定（OTA_flag / OTA_ver / UPDATE_flag=240 等），qibiji_zxl 代码目前无访问但**不能占用**（见 OTA 文档核对表 #4）；
- **250**：Marker；
- 旧工程闸门参数区（`AT24CXX_Readdatas` 批量 10×u16 的地址）——**动手前先 grep 旧工程确认实际地址**，新参数区避开一切已占用段。

建议：参数区放在 **150~199**（100 字节 = 50 个 u16 槽，余量充足），每个参数占 1 个 u16 槽，**存储方案照抄旧工程 `qibiji/HARDWARE/REG/reg.c` 的哨兵值模式**：不存"已初始化"标志，上电读到 0x0000 或 0xFFFF（空白/坏值）就用代码内默认值兜底（旧工程 `eepromToPara()` reg.c:108-122 同款判据）。三个参数的合法范围都不含 0 和 0xFFFF，哨兵判断可靠。

### 4.3 完整代码（新增 `HARDWARE/GPRS/gprs_config_param.h/.c`，未落盘）

**前置事实核对（2026-11-21）**：三个参数里只有 `stallMa` 有现成运行时接口——`ADC_SetStallThresholdMa()`（adc.c:349，默认值 `ADC_STALL_MA_DEFAULT 3500`，adc.h:27）。另外两个是**编译期宏**，运行时改不了，需要配套小改（见 4.4）。

**gprs_config_param.h**：

```c
#ifndef __GPRS_CONFIG_PARAM_H
#define __GPRS_CONFIG_PARAM_H

#include "stm32f10x.h"   /* u8/u16/u32 */

/* 远程可下发参数：白名单制，校准量一律不进本表。
   EEPROM 参数区 150~199（OTA 组 200~243、Marker 250 不可占用，见 4.2）。 */

/* 参数 key（与平台 serviceCode=setConfig 的 body.params 键名一致） */
#define GPRS_CFG_KEY_STALL_MA      "stallMa"
#define GPRS_CFG_KEY_REPORT_MS     "reportCycleMs"
#define GPRS_CFG_KEY_RAIL_LOW      "railLow"

/* 返回码 */
#define GPRS_CFG_OK            0u
#define GPRS_CFG_ERR_KEY       1u   /* 未知 key */
#define GPRS_CFG_ERR_RANGE     2u   /* 越界 */

void     GprsCfg_Init(void);                  /* 上电恢复，在 ADC/DCMOTOR/property_report 初始化之前调 */
uint8_t  GprsCfg_Set(const char *key, int v); /* 校验 + 写 EEPROM + 即时生效 */
uint16_t GprsCfg_Get(const char *key);        /* 当前生效值 */

#endif
```

**gprs_config_param.c**：

```c
#include "gprs_config_param.h"
#include "eeprom_drv.h"
#include "adc.h"
#include "property_report.h"
#include <string.h>
#include <stdio.h>

/* ---- EEPROM 槽位（见 4.2 规划；存取方案照抄旧工程 reg.c 的哨兵值模式） ---- */
#define EE_STALL_MA_VAL     150u
#define EE_REPORT_MS_VAL    152u
#define EE_RAIL_LOW_VAL     154u

/* 哨兵值：EEPROM 空白（0xFFFF）或坏值（0x0000）→ 用默认值。
   三个参数合法范围均不含这两个值，判断可靠（旧工程 eepromToPara() reg.c:108-122 同款）。 */
#define EE_SENTINEL_LO      0x0000u
#define EE_SENTINEL_HI      0xFFFFu

typedef struct
{
    const char *key;
    uint16_t    ee_val;      /* u16 值槽地址 */
    uint16_t    def_val;     /* 空白/坏值/越界时的默认值 */
    uint16_t    min;
    uint16_t    max;
} GprsCfgItem;

static GprsCfgItem s_items[3] =
{
    /* key                 val 地址          默认                          min    max */
    { GPRS_CFG_KEY_STALL_MA,  EE_STALL_MA_VAL,  ADC_STALL_MA_DEFAULT,        1000u,  0xFFFFu },  /* 范围与旧工程 reg.c:108-122 一致 */
    { GPRS_CFG_KEY_REPORT_MS, EE_REPORT_MS_VAL, PROP_REPORT_MIN_INTERVAL_MS, 1000u, 60000u },
    { GPRS_CFG_KEY_RAIL_LOW,  EE_RAIL_LOW_VAL,  ADC_RAIL_LOW,                2u,    100u  },
};

static uint16_t s_cur[3];    /* 当前生效值，下标与 s_items 对应 */

/* ---- 即时生效：调各模块的运行时接口 ---- */
static void s_apply(uint8_t idx)
{
    switch (idx)
    {
    case 0u:  ADC_SetStallThresholdMa(s_cur[0]);            break;
    case 1u:  PropertyReport_SetMinIntervalMs(s_cur[1]);    break;
    case 2u:  ADC_SetRailLow(s_cur[2]);                     break;
    default:                                                break;
    }
}

/* ---- 上电恢复 ---- */
void GprsCfg_Init(void)
{
    uint8_t i;

    /* EEPROM 自检失败：全部用默认值，设备照常跑，不要卡启动 */
    if (AT24CXX_Check() == 0u)
    {
        for (i = 0u; i < 3u; i++) { s_cur[i] = s_items[i].def_val; s_apply(i); }
        return;
    }

    for (i = 0u; i < 3u; i++)
    {
        uint16_t stored = (uint16_t)AT24CXX_ReadLenByte(s_items[i].ee_val, 2u);

        /* 哨兵判断（旧工程 reg.c:108-122 同款）：空白/坏值 → 默认值 */
        if ((stored == EE_SENTINEL_LO) || (stored == EE_SENTINEL_HI))
            s_cur[i] = s_items[i].def_val;
        else
            s_cur[i] = stored;

        /* 防御：EEPROM 里存了越界旧值时，按默认值跑 */
        if ((s_cur[i] < s_items[i].min) || (s_cur[i] > s_items[i].max))
            s_cur[i] = s_items[i].def_val;

        s_apply(i);
    }
}

static int s_find(const char *key)
{
    uint8_t i;
    for (i = 0u; i < 3u; i++)
    {
        if (strcmp(s_items[i].key, key) == 0) return (int)i;
    }
    return -1;
}

/* ---- 设置：校验 + 写 EEPROM + 生效 ---- */
uint8_t GprsCfg_Set(const char *key, int v)
{
    int idx = s_find(key);
    GprsCfgItem *it;
    uint16_t val;

    if (idx < 0)                 return GPRS_CFG_ERR_KEY;
    if ((v < 0) ||
        ((uint32_t)v > (uint32_t)s_items[idx].max) ||
        ((uint32_t)v < (uint32_t)s_items[idx].min))
        return GPRS_CFG_ERR_RANGE;

    it  = &s_items[idx];
    val = (uint16_t)v;

    AT24CXX_WriteLenByte(it->ee_val, (uint32_t)val, 2u);

    s_cur[idx] = val;
    s_apply(idx);
    return GPRS_CFG_OK;
}

uint16_t GprsCfg_Get(const char *key)
{
    int idx = s_find(key);
    if (idx < 0) return 0u;
    return s_cur[idx];
}

/* ---- getConfig：拼 {"stallMa":..,"reportCycleMs":..,"railLow":..} ---- */
uint8_t GprsCfg_BuildAllJson(char *buf, uint32_t buf_size)
{
    int n;
    n = snprintf(buf, buf_size,
                 "{\"%s\":%u,\"%s\":%u,\"%s\":%u}",
                 s_items[0].key, (unsigned)s_cur[0],
                 s_items[1].key, (unsigned)s_cur[1],
                 s_items[2].key, (unsigned)s_cur[2]);
    if ((n <= 0) || ((uint32_t)n >= buf_size)) return 0u;
    return 1u;
}
```

**分发分支**（gprs_json.c 分发段追加，仿 `setValue` 三段式）。注意现有代码各分支执行完都**落穿到函数末尾 224 行的统一 `cJSON_Delete(root)`**，所以分支内不能提前 `return`，用标志变量收尾：

```c
else if (strcmp(serviceCode->valuestring, "setConfig") == 0)
{
    cJSON *kid;
    uint8_t rc;

    params = cJSON_GetObjectItem(body, "params");
    kid = params ? params->child : NULL;   /* body.params 下允许多个键值对，逐个处理 */
    while (kid != NULL)
    {
        if (cJSON_IsNumber(kid) && (kid->string != NULL))
        {
            rc = GprsCfg_Set(kid->string, (int)cJSON_GetNumberValue(kid));
            if (rc != GPRS_CFG_OK)
            {
                GPRS_Printf("s->c setConfig %s failed (%u)\r\n", kid->string, (unsigned)rc);
                GPRS_ReplyServices(400, "setConfig rejected", "{}");
                break;    /* 任一失败整体拒绝；落到统一出口释放 cJSON 树 */
            }
        }
        kid = kid->next;
    }
    /* 循环没被 break（全部成功，或 params 为空）→ 补成功应答 */
    if (kid == NULL)
        GPRS_ReplyServices(0, "success", "{}");
}
```

> **C90 提醒**：工程按 C90 编译（ARMCC），声明必须写在**块**的开头，不能出现在语句之后。`kid`/`rc` 是 setConfig 分支的局部变量，写在 `else if {` 花括号的开头两行即可（分支块也是块，C90 合法），不必挪进函数头部声明区；只有当块内出现"先语句、后声明"时才需要上提。

`getConfig` 分支（把参数表整体拼成 JSON 回给平台）：

```c
else if (strcmp(serviceCode->valuestring, "getConfig") == 0)
{
    if (GprsCfg_BuildAllJson(s_json_buf, sizeof(s_json_buf)) != 0u)
        GPRS_ReplyServices(0, "success", s_json_buf);
    else
        GPRS_ReplyServices(500, "build failed", "{}");
}
```

**上电恢复调用点**：`USER/main.c` 里 `AT24CXX_Init()/AT24CXX_Check()` 完成后、ADC/DCMOTOR/property_report 各 Init **之前**调 `GprsCfg_Init()`——模块先用代码默认值再被 EEPROM 值覆盖，会出现"改参数后第一拍不对"的窗口。

**Keil 工程**：`gprs_config_param.c` 要加进 `SRTUV10.uvprojx` 的 HARDWARE/GPRS 分组，否则编译能过（头文件声明悬空）链接报 undefined。

**① property_report**——`PROP_REPORT_MIN_INTERVAL_MS` 是宏（property_report.h:19，使用点 property_report.c:80）：

static uint32_t s_min_interval_ms = PROP_REPORT_MIN_INTERVAL_MS;
/* property_report.c 80 行改用 s_min_interval_ms */
/* property_report.h 加声明 */
void PropertyReport_SetMinIntervalMs(uint16_t ms);

### 4.4 验证

下发 `setConfig` → 应答 0 → **断电重启** → `getConfig` 读回值一致；下发越界值 → 应答 400 且原值不变；EEPROM 拔卡/损坏（`AT24CXX_Check` 失败）时设备用默认值正常跑，不卡启动。

## 五、阶段三：OTA 开闸入口 `setUpdateValue`（占位框架已有约定）

阶段四文档已约定：本版只做**回执框架**（回 `{"updateFlag":...}`，标志位存 RAM），不实现下载。完整方案（写 EEPROM 240、与 bootloader 的 `OtaCloseUpdateGate` 对接、验证步骤）**已写入 `OTA重构操作建议.md` 阶段二的方案 B 补充**，本文不重复。要点提示：

- 标志位不能只存 RAM——复位就丢，必须落 EEPROM 240 才有意义；
- 采用 `ReSet` 的"应答先行 + 动作延后"模式（写 EEPROM 可能耗时，先回 0 再写）；
- 写入成功与否要二次确认读回，失败时应答 500，不能"回了 success 但闸没开"。

---

## 六、阶段四（可选）：`request_reply` 通用化

现状 `type=="request_reply"` 分支（gprs_json.c:155-162）是对时专用（`GPRS_ClockSync_OnReply`）。将来 `property_get` 若改成异步请求-应答模式（平台发请求 → 设备按 `id` 回），需要把该分支抽成按 `id` 匹配的通用分发。**当前三条只读指令都走同步应答，用不到**——等出现第二个异步请求再重构，现在不动。

---

## 七、实施顺序与联动

```
阶段一（3 条只读指令）──► 阶段二（setConfig + EEPROM）──► 阶段三（OTA 开闸，见 OTA 文档）
                                   │
                                   └── getConfig 与阶段二同轮实现
```

- 每阶段一个变化，落盘后逐条列出动了哪个文件哪几行；
- 阶段二动 EEPROM 前，先完成 4.2 的地址盘点（grep 旧工程参数区实际地址）；
- 阶段三与 OTA 文档阶段二方案 A（SBF-20 蓝牙迁移）是**二选一**关系，决策记录在 OTA 文档。
