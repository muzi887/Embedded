# 看门狗调试说明

> 面向本工程 `qibiji_zxl`（STM32F103 + IWDG）。说明调试前怎么配置、要看哪些窗口和变量、每个变量的含义与期望值，以及怎么判定"看门狗真的生效"。
> 配套文档：《看门狗重构操作建议.md》（实现细节）、《看门狗说明.md》（概念）。

## 一、先明确：调试通过 ≠ 看门狗成功

调试器会冻结看门狗计数，所以**调试阶段"不复位"只能说明接入正确**。真正的验收必须包含两项：

1. **该复位时会复位**：人为让程序挂死，2~3 秒后自动重启；
2. **正常流程不误复位**：完整启动 + 长时间运行，不出现中途重启。

本文最后一节的验收清单覆盖这两项。

```
_WDWORD(0xE0042004, 0x00000100)
```

- `0xE0042004` = `DBGMCU_CR`，`0x100` = bit8 `DBG_IWDG_STOP`；
- 在 Options → Debug → **Initialization File** 里选 `..\debug.ini`，每次进入调试自动执行；

### 3.1 IWDG 寄存器含义与期望值

IWDG 只有 4 个寄存器，分工是：**KR 是操作入口（启动/喂狗/解锁），PR 决定“数多快”，RLR 决定“数多久”，SR 告诉你配置有没有生效**。

| 寄存器 | 作用 | 位定义 | 本工程值 | 读写特性与判读 |
|---|---|---|---|---|
| `KR` | 键寄存器，命令入口：写入不同“魔数”执行不同操作，寄存器本身不保存状态 | 32 位，只识别三个键值：`0xCCCC`=启动计数、`0x5555`=允许写 PR/RLR、`0xAAAA`=重装计数器（喂狗） | 读回恒为 `0x00000000` | **只写**：任何读访问都返回 0，Keil 窗口看到 0 是正常的，不能据此判断写没写成功。是否喂狗要看 PR/RLR 和运行行为（见下方说明） |
| `PR` | 预分频寄存器，对 LSI 时钟分频，决定计数器**每多少微秒减 1** | `bits[2:0]`：`000`=4、`001`=8、`010`=16、`011`=32、`100`=64、`101`=128、`110`=256；其余位保留 | `0x04` → 分频因子 4×2⁴ = **64** | 写入前必须先写 `KR=0x5555` 解锁；写入后 `SR.PVU` 置 1，与 LSI 同步完成后硬件清零。运行中可改，但本工程只在 `WDG_Init()` 设置一次 |
| `RLR` | 重装值寄存器，决定计数器**从多少开始往下数**；数到 0 触发复位 | `bits[11:0]`：0~4095；高位保留 | `0x000007C6` = **1990** | 同样需要先解锁；写入后 `SR.RVU` 置 1。每次喂狗（`KR=0xAAAA`）都会把计数器重新装回这个值 |
| `SR` | 状态寄存器，只反映 PR/RLR 的更新进度，不控制任何功能 | `bit0 PVU`：预分频值正在更新；`bit1 RVU`：重装值正在更新；其余保留 | `0x00` | **只读**。写 PR/RLR 后硬件自动置位，同步完成后自动清零。长期为 1 说明 LSI 未起振或写入未成功 |

**三者关系**：计数频率 = `f_LSI / (4 × 2^PR)`，一次超时的计数次数 = `RLR`，因此：

```text
复位时间 = 分频系数 × 重装值 ÷ LSI频率
         = 64 × 1990 ÷ f_LSI
```

代入本工程参数：
- LSI 60kHz → **2123ms（最短，设计上限）**
- LSI 40kHz → 3184ms（标称）
- LSI 30kHz → 4245ms（最长）

**判读要点**：必须 `PR=4`、`RLR=1990`、`SR=0` **同时成立**，才说明配置已写入并同步完成。只看到 PR/RLR 正确但 SR 非 0，说明值还在同步中、尚未真正生效。

**为什么 `KR` 始终读为 0**：RM0008 明确 `IWDG_KR` 是只写寄存器，读回固定为 0，所以窗口里的 0 不代表 `IWDG_Enable()` / `IWDG_ReloadCounter()` 没执行。确认写入实际发生的三个依据：

- `PR`/`RLR` 已变成 `0x04`/`0x7C6` 且 `SR=0`——这两个寄存器必须先用 `KR=0x5555` 解锁才能写，说明键写入链路是通的；
- 计数确实在跑：停止喂狗 2~3 秒后芯片复位；
- 断点停在 `WDG_Feed()` 后看反汇编，对 `0x40003000` 的写操作应带 `0xAAAA` 常量（`WDG_Init()` 里则是 `0xCCCC`）。

## 四、Watch 哪些变量

### 4.1 全局变量（冷启动即可观察）

| 变量 | 类型 / 位置 | 含义 | 期望值 / 判读 |
|---|---|---|---|
| `g_wdg_reset_cause` | `uint8_t`，[wdg.c](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/WDG/wdg.c) | 本次复位是否由 IWDG 引起 | 上电/手动复位为 `0`；看门狗复位后为 `1`。注意它在 `WDG_Init()` 里读取后立即清标志 |
| `g_sys_ms` | `uint32_t`，timer.c | TIM3 10ms 中断累计的毫秒数 | 正常每 10ms +10；停在断点期间几乎不增长，可用于比较两断点之间的**代码执行时长**（精度 10ms） |
| `g_motor_warning_curr_upper` | `uint16_t` | 堵转电流阈值（mA），EEPROM 读出 | 默认 `3500`（0x0DAC），合理范围 500~10000 |
| `g_gate_maxheight` | `uint16_t` | 闸门最大高度（mm） | 默认 `1000`（0x03E8），合理范围 200~5000 |
| `g_gate_maxturns` | `uint16_t` | 闸门最大圈数 | 默认 `80`（0x0050），合理范围 10~5000；0 表示未标定 |

### 4.2 局部变量（在 AT24CXX_Check 处观察）

停在 [eeprom_drv.c](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/EEPROM/eeprom_drv.c) 的 `AT24CXX_Check()` 内部时，手动把以下变量加入 Watch：

| 变量 | 含义 | 期望值 |
|---|---|---|
| `temp` | 标记字节 `EE_ADDR` 的读值 | `0x55` 表示已初始化过；`0xFF` 表示空白 |
| `mc` | 0x0004 读出的堵转阈值 | 3500（0x0DAC） |
| `mh` | 0x0006 读出的最大高度 | 1000（0x03E8） |
| `mt` | 0x0008 读出的最大圈数 | 80（0x0050） |

判读：若 `temp==0x55` 但任一参数越界（`mc==0`、`mh<200`、`mt<10`），会打印 `24C02 param out of range: reseed` 并重新播种；播种后重新上电应不再出现该打印。

### 4.3 不建议作为判据的变量

- `s_tick_10ms`（timer.c 内 static）只在中断置位、主循环消费，停断点时通常为 0，不能反映节拍是否正常，看 `g_sys_ms` 即可；
- 中断里出现的任何值都不能用来证明"主循环还活着"。

### 阶段 3：长阻塞段

**关键前提**：TIM3 10ms 时钟在 `main.c:93` 才启动，LCD（76）、EEPROM 首次播种（83）、`GPRS_4G_Init()` 首次调用（90）的喂狗点都在这之前——这些位置 `g_sys_ms` 恒为 0，**不能用 g_sys_ms 差值验证**，应改用断点命中次数 + 全程无复位作为判据。

例外是**运行期**的 4G 复位：`GPRS_4G_Reset()` 由 `GPRS_AT_StateMachine()`（[gprs_at.c:247](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_at.c#L247)，离线 ≥60s）和 `NetLiveness`（[net_liveness.c:141/181](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/net_liveness.c#L141)）在 `while(1)` 内调用，此时 TIM3 已启动；它末尾还会再调 `GPRS_4G_Init()`（[gprs_4g.c:68](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_4g.c#L68)）。因此这两处的喂狗**可以用 `g_sys_ms` 差值验证**（≈1000ms / ≈500ms）。EEPROM 运行期写入同理（见下表第 5 项）。

**“1.5s 阻塞”指什么**：`delay_ms()` 是 SysTick 空转轮询（[delay.c:136](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/SYSTEM/delay/delay.c#L136)），CPU 在此期间无法返回 `while(1)`，`main.c:101` 的 `WDG_Feed()` 不会执行；但 TIM3/USART 等中断照常响应，`g_sys_ms` 继续计数。`GPRS_4G_Reset()` 的阻塞 = `delay_ms(1000)`（[gprs_4g.c:65](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_4g.c#L65)） + `GPRS_4G_Init()` 内 `delay_ms(500)`（[gprs_4g.c:54](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_4g.c#L54)） = **1.5s**，其间仅靠 1000ms（[gprs_4g.c:67](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_4g.c#L67)）和 1500ms（[gprs_4g.c:56](file:///D:/code2/software/vue/program/Embedded/qibiji/qibiji_zxl/HARDWARE/GPRS/gprs_4g.c#L56)）两处喂狗续命，距最坏窗口 2123ms 仅余约 600ms，是全工程余量最小的一段。副作用：这 1.5s 内按键、LCD、电机状态机均停止服务（只在 4G 离线 ≥60s 时发生）。

1. 冷启动，分别在 LCD12864_Init、AT24CXX_WriteOneByte、GPRS_4G_Init 三个函数内的 `WDG_Feed()` 处打断点，确认全部命中、命中过程中无复位；
2. 进主循环后触发一次 EEPROM 写入，在 EEPROM 写路径的 `WDG_Feed()` 处断，记录每字节约 10ms 命中一次。远程配置下发尚未接入（`dcmotor_param_save_*` 无调用者），实际做法：在 `while(1)` 内临时加一次性注入

```c
/* 临时验证用，验完删除 */
{
    static uint8_t s_eeprom_test_done = 0u;
    if (s_eeprom_test_done == 0u)
    {
        s_eeprom_test_done = 1u;
        dcmotor_param_save_warn_curr(3500u);   /* 写 2 字节，WDG_Feed 命中 2 次；3500 为默认值，无副作用 */
    }
}
```

3. 全程无复位、串口 banner 只打印一次。

## 七、故障注入：验证"该复位时会复位"

**必须在无调试器（或调试器不暂停内核）的条件下做**，否则 IWDG 被冻结，测试无效。

1. 临时在 `while(1)` 开头插入 `while (1);`；
2. 编译烧录，断开调试器，上电；
3. 预期 2~3 秒后芯片复位并重新走启动流程（串口再次打印 `qibiji_zxl KEY test ready`）；
4. 重新连接调试器，`g_wdg_reset_cause` 应为 `1`，`RCC->CSR` bit29 为 1；
5. 删除死循环，恢复正式固件并重新烧录。

若 10 秒仍不复位：检查 IWDG 是否真的使能（`PR`/`RLR` 是否为 `4`/`1990`、`WDG_Init()` 是否执行到；`KR` 读回恒为 0，不能作为判据）、`.ini` 冻结位是否只在调试时生效、是否有人在 `delay_ms()` 或中断里喂狗。

**故障注入记录表：**

| 记录项 | 期望值 | 实测值 | 结论 | 备注 |
|---|---|---|---|---|
| 复位周期（挂死→复位） | 2~3s | **3.27s** | 通过 | 由 `1990×64/LSI` 反推 LSI ≈ 38.9kHz，落在 STM32F103 规格（30~60kHz）内，说明 `PR=4 / RLR=1990` 正确 |
| 连续复位次数 | ≥3 | 13 次（21:55:47~21:59:09） | 通过 | 每轮都完整走完启动流程后再次挂死，无一次"卡死不复位" |
| 启动段是否被误咬 | 否 | 否 | 通过 | 每轮启动耗时 2.13s（LCD 1.5s + EEPROM + `GPRS_4G_Init()` 0.5s），期间 3 处喂狗生效，未提前复位 |
| 串口复位原因 | `reset by IWDG` | 全部为 `reset by IWDG` | 通过 | 仅烧录后首次启动为 `no IWDG reset`（复位源为调试器/上电，非看门狗），可作为基准对照 |

## 八、常见异常与判读

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 按 Step 无反应 / 界面停住 | 停顿时 IWDG 已复位芯片，Keil 视图与内核失步 | 配好 Stop Watchdog Counters 或 `.ini`，重进调试 |
| Debug → Settings 报 "no configuration options" | Device 页未选具体型号 | 选 STM32F103RC 等实际型号 |
| 链接报 `Undefined symbol DBGMCU_Config` | 固件调用了 `DBGMCU_Config()` | 删除该调用，改用调试器配置 |
| `KR` 显示 `0x00000000` | KR 只写，读访问恒返回 0 | 正常，不处理；用 `PR/RLR/SR` 与喂狗行为判断 |
| `SR.PVU` 长期为 1 | 预分频写入未同步 | 继续运行再观察；仍为 1 时查 LSI/供电 |
| 每次上电都打印 reseed | 参数越界或标记字节失效 | 对照 4.2 的默认值检查 EEPROM 内容 |
| `g_sys_ms` 长时间不增长 | TIM3 未启动或中断未使能 | 检查 `TIM3_10ms_Init()` 调用位置与 NVIC |
| 调试时正常、脱机反复重启 | 某段阻塞超过 2123ms 且未喂狗 | 按 §5 补喂狗点或拆段 |
