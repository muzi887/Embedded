# DS1302（RTC）重构操作建议

> 本模块是**设备时钟**的唯一来源，也是 GPRS 阶段四对时（`sys.timeSync`）的落地端。独立于 GPRS 阶段一~三，建议与 [EEPROM重构操作建议.md](./EEPROM重构操作建议.md) 一起在阶段四之前完成。
>
> 阶段四文档 §1 只保留摘要，完整实现以本文件为准。

## 1. 原工程现状

| 项 | 内容 |
|---|---|
| 驱动文件 | `HARDWARE/DS1302/ds1302.c` / `ds1302.h` |
| 引脚 | **PC6 = RST(CE)**、**PC7 = DAT(I/O)**、**PC8 = CLK**（`GPIOC`，DAT 配置为开漏 `Out_OD`） |
| 通信方式 | 三线位操作（bit-bang），无外设 |
| 时间格式 | BCD；寄存器顺序 = 秒 / 分 / 时 / 日 / 月 / 周 / 年（年只有 2 位，00-99 → 2000-2099） |
| 读写地址 | 写 `0x80/0x82/0x84/0x86/0x88/0x8A/0x8C`，读 `0x81/0x83/0x85/0x87/0x89/0x8B/0x8D`，写保护 `0x8E`（写前清 0、写完置 0x80） |
| 对外接口 | `ds1302_init()`、`ds1302_dataread(char ttt[7])`、`ds1302_settime(uint8_t dat[7])`、`ds1302_setch()`、`read_1302()`、`write_1302()` |
| 时区约定 | **DS1302 存东八区本地时**；平台 `serverTime` 是 UTC 毫秒 → 写入时 +8h，读出转 unix 时 −8h |

原工程已经有一层"unix 秒 ↔ DS1302"的转换代码（`rtc_get_unix_sec` / `unix_sec_to_calendar` 等），但它们**散落在 `gprs_JSON.c` 里**，和业务逻辑混在一起。重构就是把它们收拢成独立模块。

## 2. 原工程的三个缺陷（重构时必须修）

### F2-1 `ds1302_settime()` 的回读校验是错的

```c
ds1302_dataread(ttt);            /* ttt[0..6] 已是十进制 */
for (i = 1; i < 7; i++)
{
    if (ttt[i] == dat[i])        /* dat[] 是 BCD！十进制 vs BCD 永远不相等 */
        res = 0;
    else { res = 0xFF; break; }
}
```

- `dat[i]` 是 BCD（如 12 秒 = `0x12`），`ttt[i]` 是十进制（12），**只要数字里有 10 以上就不可能相等**；
- 循环从 `i = 1` 开始，**秒从未被校验**；
- 结果：写入成功也返回 `0xFF`，调用方无法据此判断对时是否真正生效。

**修法**：把 `dat[]` 转成十进制后再比较，或直接比较 BCD（读回原始字节）。重构版在 `gprs_rtc.c` 里做校验，不再让驱动返回错误语义。

### F2-2 所有 `delay_us()` 都被注释掉了

`write_1302byte()` / `read_1302()` 里原本有 1~3us 的延时，现在全部注释。DS1302 的 SCLK 高/低电平有最小宽度要求，72MHz 下 GPIO 翻转极快，**多数板子能跑，但属于"卡在时序边缘"**。如果对时偶发失败或读回全 `0x00/0xFF`，第一件事就是把 1us 延时加回来。

### F2-3 位操作没有临界区保护

`read_1302` / `write_1302` 是"拉 RST → 逐位收发 → 放 RST"的长序列，中间若被 EXTI（LINK 跳变）或 USART 中断打断，DS1302 会认为通信异常。重构版在 `gprs_rtc.c` 的读写入口加开/关中断的临界区。

## 3. 重构目标

1. 驱动层 `ds1302.c/h` **从原工程拷贝**，只做最小修正（签名、类型、文件头注释），不改通信时序；
2. 新增抽象层 `gprs_rtc.h/.c`，把 unix 换算、时区、BCD、周计算全部收进来，**业务层只看到 `GetUnixSec() / GetMsOfSec() / Set()`**；
3. 对时逻辑（发请求 / 收回执 / 重试）作为独立小节写清楚，落到 `gprs_json.c`；
4. 修掉 F2-1，并给 F2-2、F2-3 留可开关的修正点。

## 5. 驱动层：拷贝 + 最小修正

拷贝 `ds1302.c/h` 后只改这几处：

1. **头注释**统一为本工程的块注释风格（文件职责一句话）；
2. `void ds1302_init()` → `void ds1302_init(void)`（声明与定义保持一致，`-Wstrict-prototypes` 友好）；
3. `u8` → `uint8_t` / `uint16_t`（避免依赖 `sys.h` 的旧 typedef）；
4. `ds1302_setch()` 里两行 `printf` 换成 `GPRS_Printf()`，或者直接删掉；
5. `ds1302_settime()` **保留原样**（返回值不可信，重构版不依赖它），或者按 F2-1 修掉——两者择一，不要既依赖又保留错误实现。

其余一律不动：寄存器地址表、`write_1302byte` 的位序、`read_1302` 的采样点、写保护 `0x8E` 的开关顺序。

## 7. 抽象层 `gprs_rtc.c`（完整实现）

```c
#include "gprs_rtc.h"
#include "ds1302.h"
#include "timer.h"          /* g_sys_ms */
#include <stdio.h>

/* DS1302 holds local time; platform serverTime is UTC. */
#define RTC_TZ_OFFSET_SEC (8UL * 3600UL)

static const uint8_t s_days_in_month[12] =
    {31u, 28u, 31u, 30u, 31u, 30u, 31u, 31u, 30u, 31u, 30u, 31u};

static uint8_t s_is_leap(int y)
{
    return (uint8_t)((y % 4 == 0) && ((y % 100 != 0) || (y % 400 == 0)));
}

/* 1 = Sunday ... 7 = Saturday, matches DS1302 week register. */
static uint8_t s_weekday(int y, int m, int d)
{
    static const int t[12] = {0, 3, 2, 5, 0, 3, 5, 1, 4, 6, 2, 4};
    if (m < 3)
        y -= 1;
    return (uint8_t)(((y + y / 4 - y / 100 + y / 400 + t[m - 1] + d) % 7) + 1);
}

/* unix seconds -> calendar (UTC+8 local) */
static void s_unix_to_cal(uint32_t utc_sec, int *year, int *mon, int *day,
                          int *hour, int *min, int *sec)
{
    uint32_t t = utc_sec + RTC_TZ_OFFSET_SEC;
    uint32_t days = t / 86400UL;
    uint32_t rem  = t % 86400UL;
    int y = 1970;
    int m;

    *hour = (int)(rem / 3600UL);
    rem %= 3600UL;
    *min = (int)(rem / 60UL);
    *sec = (int)(rem % 60UL);

    for (;;)
    {
        int dim = 365 + (int)s_is_leap(y);
        if (days < (uint32_t)dim)
            break;
        days -= (uint32_t)dim;
        y++;
    }
    *year = y;

    for (m = 1; m <= 12; m++)
    {
        int dim = (int)s_days_in_month[m - 1];
        if (m == 2)
            dim += (int)s_is_leap(y);
        if (days < (uint32_t)dim)
            break;
        days -= (uint32_t)dim;
    }
    *mon = m;
    *day = (int)days + 1;
}

/* calendar (UTC+8 local) -> unix seconds */
static uint32_t s_cal_to_unix(int year, int mon, int day, int hour, int min, int sec)
{
    uint32_t days = 0;
    int y, m;

    if (year < 1970 || mon < 1 || mon > 12 || day < 1 || day > 31)
        return 0u;

    for (y = 1970; y < year; y++)
        days += (uint32_t)(365 + (int)s_is_leap(y));
    for (m = 1; m < mon; m++)
    {
        days += s_days_in_month[m - 1];
        if (m == 2)
            days += s_is_leap(year);
    }
    days += (uint32_t)(day - 1);

    {
        uint32_t local_sec = days * 86400UL
                           + (uint32_t)hour * 3600UL
                           + (uint32_t)min * 60UL
                           + (uint32_t)sec;
        return (local_sec >= RTC_TZ_OFFSET_SEC) ? (local_sec - RTC_TZ_OFFSET_SEC) : 0u;
    }
}

static uint8_t s_dec2bcd(int v)
{
    return (uint8_t)(((v / 10) << 4) | (v % 10));
}

void GPRS_RTC_Init(void)
{
    ds1302_init();
}

void GPRS_RTC_Set(uint32_t utc_sec)
{
    uint8_t bcd[7];
    int year, mon, day, hour, min, sec;

    if (utc_sec == 0u)
        return;

    s_unix_to_cal(utc_sec, &year, &mon, &day, &hour, &min, &sec);
    if (year < 2000 || year > 2099)
        return;

    bcd[0] = s_dec2bcd(sec);
    bcd[1] = s_dec2bcd(min);
    bcd[2] = s_dec2bcd(hour);
    bcd[3] = s_dec2bcd(day);
    bcd[4] = s_dec2bcd(mon);
    bcd[5] = s_weekday(year, mon, day);
    bcd[6] = s_dec2bcd(year % 100);

    ds1302_settime(bcd);   /* return value unreliable: see F2-1 */
}

uint32_t GPRS_RTC_GetUnixSec(void)
{
    char t[7];   /* decimal, order: sec/min/hour/day/mon/week/year */

    __disable_irq();          /* F2-3: protect the bit-bang sequence */
    ds1302_dataread(t);
    __enable_irq();

    if ((uint8_t)t[6] > 99u || (uint8_t)t[4] < 1u || (uint8_t)t[4] > 12u ||
        (uint8_t)t[3] < 1u || (uint8_t)t[3] > 31u)
        return 0u;            /* never synced or battery lost */

    return s_cal_to_unix(2000 + (int)(uint8_t)t[6], (int)(uint8_t)t[4],
                         (int)(uint8_t)t[3], (int)(uint8_t)t[2],
                         (int)(uint8_t)t[1], (int)(uint8_t)t[0]);
}

uint16_t GPRS_RTC_GetMsOfSec(void)
{
    return (uint16_t)(g_sys_ms % 1000u);
}

int64_t GPRS_RTC_NowMs(void)
{
    return (int64_t)GPRS_RTC_GetUnixSec() * 1000LL + (int64_t)GPRS_RTC_GetMsOfSec();
}
```

### 几个实现要点

- **`__disable_irq()` 只在 `GetUnixSec` 里加**：读 7 个字节 ≈ 7 × 16 个 GPIO 翻转，72MHz 下约 50~100us，对 10ms 主循环无影响，但必须在 `dataread` 外面包住，不能在驱动内部包（否则 `ds1302_settime` 内部回读会死锁）。
- **未校时时返回 0**：年份非法（未对时 / 电池掉电）直接返回 0，调用方可据此判断"时间不可信"，不要把 1970 年时间戳发给平台。
- **周计算用 Sakamoto 公式**：比"累加天数再取模"省几十行循环，结果 1-7 直接对应 DS1302 寄存器。
- **时区只在抽象层出现一次**：`RTC_TZ_OFFSET_SEC` 只在这个文件里出现，其他模块拿到的全是 UTC unix 秒。

## 8. 对时逻辑（`sys.timeSync`）

对时是"**设备主动请求 → 平台回执 → 写 RTC → 放行首帧心跳**"的四步闭环。

### 8.1 状态与常量（`gprs_json.c` 内部）

```c
#define GPRS_CLOCK_MAX_ATTEMPTS     3u
#define GPRS_CLOCK_TX_TIMEOUT_MS    3000u
#define GPRS_CLOCK_WARMUP_MS        2000u    /* 进 NORMAL 后的热身，等模块建好会话 */
#define GPRS_CLOCK_PROBE_MS         60000u   /* 通道未确认时的探测节奏 */
#define GPRS_CLOCK_PROBE_MAX        5u       /* 探测次数上限，超了喂看门狗 */
static const uint32_t s_clock_wait_ms[GPRS_CLOCK_MAX_ATTEMPTS] = {15000u, 30000u, 60000u};

static uint8_t  s_clock_pending;          /* 1 = 有一次请求在途 */
static uint8_t  s_clock_attempt_idx;      /* 0..2 → 15/30/60s */
static uint8_t  s_clock_chan_ok;          /* 1 = 本次会话收到过下行 */
static uint8_t  s_clock_warmup_pending;   /* 1 = 还在热身窗口内 */
static uint8_t  s_clock_probe_cnt;        /* 通道未确认期间已探测的次数 */
static uint32_t s_clock_attempt_tick;     /* 本次请求发出的时刻 */
static uint32_t s_clock_warmup_tick;      /* 进入 NORMAL 的时刻 */
static char     s_clock_pending_id[24];   /* 在途 id，回执必须匹配 */
```

> `s_clock_is_probe` 已删除：通道确认改由 `s_clock_chan_ok` + 探测计数表达，见 §8.4。

### 8.2 发：一次尝试

```c
static void GPRS_ClockSync_IssueAttempt(void)
{
    char json[UART_TX_JSON_LEN];
    char id_buf[24];
    int64_t ts = GPRS_RTC_NowMs();

    snprintf(id_buf, sizeof(id_buf), "%lld", (long long)ts);

    snprintf(json, sizeof(json),
             "%u,{"
             "\"id\":\"%s\","
             "\"productKey\":\"%s\","
             "\"deviceKey\":\"%s\","
             "\"type\":\"request\","
             "\"body\":{\"requestCode\":\"sys.timeSync\"}"
             "}",
             (unsigned)TOPIC_REQUEST_INVOKE, id_buf,
             GPRS_PRODUCT_KEY, GPRS_DEVICE_KEY);

    snprintf(s_clock_pending_id, sizeof(s_clock_pending_id), "%s", id_buf);
    s_clock_attempt_tick = g_sys_ms;
    s_clock_pending = 1u;

    /* 回执由 id 匹配，这里不重发，避免同一 id 被平台去重吃掉 */
    UartTx_Push_JSON(json, (uint16_t)strlen(json), id_buf, NULL,
                     GPRS_CLOCK_TX_TIMEOUT_MS, 0u);
}
```

**为什么 id 用时间戳**：平台按 `id` 去重，重试必须换新 id，否则重发会被当成重复请求丢弃。

### 8.3 收：回执处理

```c
static void GPRS_ClockSync_OnReply(cJSON *root)
{
    cJSON *body   = cJSON_GetObjectItem(root, "body");
    cJSON *code   = body ? cJSON_GetObjectItem(body, "code") : NULL;
    cJSON *output = body ? cJSON_GetObjectItem(body, "output") : NULL;
    cJSON *st     = output ? cJSON_GetObjectItem(output, "serverTime") : NULL;
    double ms;

    if (!cJSON_IsObject(body))
        return;

    s_clock_chan_ok = 1u;            /* a reply is the strongest channel evidence */

    /* F1: business failure must also release the gate, otherwise the first
       heartbeat is locked until the 24h timeout */
    if (cJSON_IsNumber(code) && (int)cJSON_GetNumberValue(code) != 0)
    {
        GPRS_Printf("[RTC] timeSync failed, code=%d\r\n",
                    (int)cJSON_GetNumberValue(code));
        s_clock_pending = 0u;
        NetLiveness_OnTimeSyncFail();
        return;
    }

    /* serverTime is 13 digits: MUST read as double, valueint overflows */
    if (!cJSON_IsNumber(st))
    {
        s_clock_pending = 0u;
        NetLiveness_OnTimeSyncFail();
        return;
    }

    ms = cJSON_GetNumberValue(st);
    if (ms <= 0.0)
    {
        s_clock_pending = 0u;
        NetLiveness_OnTimeSyncFail();
        return;
    }

    GPRS_RTC_Set((uint32_t)(ms / 1000.0));
    s_clock_pending = 0u;
    s_clock_attempt_idx = 0u;

    NetLiveness_OnTimeSyncOk();      /* release first heartbeat */
    GPRS_Printf("[RTC] timeSync ok\r\n");
}
```

三个容易踩的点：

1. **`serverTime` 必须用 `cJSON_GetNumberValue()` 读成 `double`**。13 位毫秒（如 `1785243312510`）远超 `int` 范围，`valueint` 会溢出成负数或截断。
2. **`code != 0` 也必须回调 `OnTimeSyncFail()`**，否则心跳门槛永远不放行（原工程 F1）。
3. **回执 id 匹配是可选加固**：当前实现只校验 `body` 存在，不比对 id。若担心重试期间收到旧回执，可在 `OnReply()` 里加一行比较 `root.id` 与 `s_clock_pending_id`，不一致直接丢弃。

### 8.4 驱动：热身 + 探测 + 超时重试

```c
void GPRS_ClockSync_Process(void)
{
    uint32_t wait_ms;

    /* 0) warm-up: the MCU-side NORMAL does not mean the module has finished
     *    attaching / subscribing, so hold the first frame for 2 s */
    if (s_clock_warmup_pending != 0u)
    {
        if ((uint32_t)(g_sys_ms - s_clock_warmup_tick) < GPRS_CLOCK_WARMUP_MS)
            return;
        s_clock_warmup_pending = 0u;
        GPRS_ClockSync_Start();
        return;
    }

    if (s_clock_pending == 0u)
        return;

    /* 1) probe mode: no downlink seen on this session yet, so a missing reply
     *    proves nothing. Keep one frame in flight at a 60 s cadence and do NOT
     *    consume the 15/30/60 retry budget. */
    if (s_clock_chan_ok == 0u)
    {
        if ((uint32_t)(g_sys_ms - s_clock_attempt_tick) < GPRS_CLOCK_PROBE_MS)
            return;

        if (s_clock_probe_cnt < 0xFFu)
            s_clock_probe_cnt++;

        if (s_clock_probe_cnt >= GPRS_CLOCK_PROBE_MAX)
        {
            s_clock_probe_cnt = 0u;
            NetLiveness_OnTimeSyncFail();   /* feed the stuck-timeSync watchdog */
        }

        GPRS_Printf("[RTC] channel unconfirmed, re-probe\r\n");
        GPRS_ClockSync_IssueAttempt();
        return;
    }

    /* 2) normal retry: 15 / 30 / 60 s, then give up */
    wait_ms = s_clock_wait_ms[s_clock_attempt_idx];
    if ((uint32_t)(g_sys_ms - s_clock_attempt_tick) < wait_ms)
        return;

    if ((uint8_t)(s_clock_attempt_idx + 1u) >= GPRS_CLOCK_MAX_ATTEMPTS)
    {
        GPRS_Printf("[RTC] timeSync give up after %u attempts\r\n",
                    (unsigned)GPRS_CLOCK_MAX_ATTEMPTS);
        s_clock_pending = 0u;
        s_clock_attempt_idx = 0u;
        NetLiveness_OnTimeSyncFail();
        return;
    }

    s_clock_attempt_idx++;
    GPRS_ClockSync_IssueAttempt();
}
```

**为什么要有探测模式**：模块上电后约 5 秒会短暂失锁重注册，这段时间发出的帧会被 `AT+CACHEN=OFF` 直接丢弃。实测一次开机 3 次重试全部打在这个窗口里，105 秒就 `give up`，但其实链路 2 秒后就恢复了。探测模式把"通道没确认"和"平台不回"区分开：没确认时只维持一发一收，不烧重试次数。

### 8.5 入口函数 + 触发时机

```c
void GPRS_ClockSync_Start(void)
{
    if (s_clock_pending != 0u)
        return;
    s_clock_attempt_idx = 0u;
    GPRS_ClockSync_IssueAttempt();
}

void GPRS_ClockSync_Reset(void)
{
    s_clock_pending        = 0u;
    s_clock_attempt_idx    = 0u;
    s_clock_chan_ok        = 0u;   /* new session: downlink unconfirmed again */
    s_clock_warmup_pending = 0u;
    s_clock_probe_cnt      = 0u;
    s_clock_pending_id[0]  = '\0';
}

void GPRS_ClockSync_OnNormal(void)
{
    GPRS_ClockSync_Reset();
    s_clock_warmup_pending = 1u;
    s_clock_warmup_tick = g_sys_ms;
    GPRS_Printf("[RTC] warm-up %ums before first timeSync\r\n",
                (unsigned)GPRS_CLOCK_WARMUP_MS);
}

void GPRS_ClockSync_OnDownlink(void)
{
    if (s_clock_chan_ok != 0u)
        return;

    s_clock_chan_ok = 1u;
    s_clock_probe_cnt = 0u;
    GPRS_Printf("[RTC] downlink confirmed, normal retry mode\r\n");

    if (s_clock_pending != 0u)
    {
        /* the in-flight probe now starts the normal 15/30/60 clock */
        s_clock_attempt_idx = 0u;
        s_clock_attempt_tick = g_sys_ms;
    }
}
```

| 时机 | 动作 | 理由 |
|---|---|---|
| 进入 `ST_NORMAL` | `GPRS_ClockSync_OnNormal()` | 清状态 + 起 2 s 热身（`gprs_at.c` 的 `ST_AT_WAIT` 完成分支调用） |
| 热身到点 | `GPRS_ClockSync_Start()` | 由 `Process()` 内部触发，不直接写在状态机里 |
| 每轮主循环 | `GPRS_ClockSync_Process()` | 热身 / 探测 / 超时判定 |
| 解析出任一帧下行 | `GPRS_ClockSync_OnDownlink()` | 通道确认，从探测切到正式重试；放在 `cJSON_Parse` 成功之后、`NetLiveness_IsAck` 之前 |
| 收到 `type == "request_reply"` | `GPRS_ClockSync_OnReply(root)` | 写 RTC + 放行心跳；放在 `ValidateServerJson` **之前**（回执不带 `serviceCode` 等业务字段） |
| 链路掉线确认 / 模块硬复位 | `GPRS_ClockSync_Reset()` | 清 `pending`、重试计数、通道确认，紧跟 `UartTx_Queue_Init()` |

> 掉线必须调 `Reset()`。否则队列里那帧被丢掉后 `s_clock_pending` 仍是 1，重连后 `Start()` 会被 `if (s_clock_pending) return;` 直接挡掉，之后的重试计时还沿用被丢掉那一帧的时刻。

### 8.6 为什么心跳必须等对时

心跳一旦通了，`NetLiveness` 的 miss 计数就归零，会掩盖"校时一直失败"这件事。校时失败意味着之后所有属性/事件上报都带错误时间戳，比晚上线几分钟严重得多。所以顺序**硬性固定**：

```
3 条初始化 AT（ICCID/MQTTCID/CSQ） → sys.timeSync → 首帧心跳
        ↑                                  ↑            ↑
     gprs_at.c                     gprs_json.c      netliveness.c
```

`NetLiveness_OnTimeSyncOk()` 放行，`OnTimeSyncFail()` 记失败次数（`netliveness.c` 里连续失败会触发模块硬复位）。

## 9. main 接线

```c
int main(void)
{
    /* ... 已有外设 init ... */
    TIM3_10ms_Init();            /* g_sys_ms 开始走（TIMER/timer.c） */
    GPRS_PORT_Init(115200);
    GPRS_RTC_Init();             /* ds1302_init()：GPIO 配置 */
    GPRS_4G_Init();              /* 复位 4G 模块 */

    /* ... */
}
```

顺序约束：

- **`TIM3_10ms_Init()` 必须在前**：`GetMsOfSec()` 依赖 `g_sys_ms`；
- **`GPRS_RTC_Init()` 不依赖 4G**，但必须在第一次 `GPRS_RTC_Set/Get` 之前；
- **不要**在 `GPRS_4G_Init()` 之前调用 `GPRS_RTC_GetUnixSec()`（会阻塞住拿不到时间），它只做 GPIO 配置，开销极小。

## 10. 验证清单

1. **驱动连通性**：上电后打一行 `GPRS_RTC_GetUnixSec()`，若返回 0 说明未校时或电池掉电（正常，进入第 2 步）。
2. **对时成功**：进 NORMAL 2s 后串口出现 `[RTC] timeSync ok`；LCD/调试口读回的日期与平台一致（注意是东八区本地时）。
3. **心跳放行**：`NetLiveness_IsWaitingTimeSync()` 从 1 变 0，随后 120s 内出现首帧心跳。
4. **业务失败重试（F1）**：让平台回 `code != 0`，确认串口打了 `timeSync failed`，且 15s 后重发（**id 已变**），而不是锁死。
5. **13 位时间戳精度**：确认 `GPRS_RTC_NowMs()` 打印出来是 13 位（约 1.78e12），不是负数或 10 位。
6. **回读校验（F2-1）**：`GPRS_RTC_Set(t)` 之后立刻 `GPRS_RTC_GetUnixSec()`，两者差值应 ≤ 2 秒；若每次都不一致，说明驱动时序有问题（见 F2-2）。
7. **掉电保持**：断电 10 秒（电池在）后上电，`GetUnixSec()` 应返回接近断电时刻的时间，而不是 0。
8. **临界区（F2-3）**：对时瞬间用示波器看 PC6/PC8，确认 RST 拉高到拉低之间没有异常拉长（说明没被中断打断）。
