按键模块（KEY）说明

从「现在什么样」到「打算改成什么样」 · 只讲按键，不谈 4G、电机、显示屏的实现细节

新工程 qibiji_zxl HARDWARE/KEY 2026-11-12
一句话版本：按键模块像楼下的门房，只该说「刚有人按了 2 号键，一次」， 不该替屋里的人决定开门还是报警。现在它把消息贴在公共公告栏上，谁都能看、没人负责撕， 于是同一条消息常常被重复执行。我们打算改成：门房把纸条投进自己的信箱，前台来取一张、取走即清。

1. 这块代码到底是干什么的

面板上有 5 个按键。这块代码负责把「引脚上的电平变化」翻译成「一次按键事件」。

它其实只需要做三步：

  1. 看一眼：5 个引脚现在是被按下（0）还是松开（1）。
  2. 确认一下：按键按下的瞬间电平会抖几下，要连着确认几次才算真按了（这叫消抖）。
  3. 报一次：告诉主程序「按了哪一颗」，而且一次按下只报一次。

至于「这个键现在该翻页、该改参数、还是该让闸门停下来」，不是它该管的事——同一个键在首页和在设置页含义不同，判断权应该在主程序（或者页面状态）手里。

2. 先认识硬件

按键一端接地，按下就把引脚拉成 0；松开时靠一颗 4.7K 电阻拉回 1，旁边还有 100nF 电容先把毛刺滤掉。所以代码里到处写的 == 0 就是「按下了」。

面板丝印单片机引脚代码里现在的名字对得上吗
K1 UPPD15KEY_UP对
K2 DOWNPA15KEY_DOWN对
K5 STOPPA11KEY_ENTER不对
K4 SETPA12KEY_LEFT不对
K3 CAN（取消）PC9KEY_RIGHT不对

LEFT / RIGHT / ENTER 这三个名字是从别的模板抄来的方向键命名，跟这台设备的面板丝印对不上。更绕的是：同一个 STOP 键，在电机里当「停止」用，在页面里当「确认 / 回首页 / 参数下一位」用。

3. 现在的数据是怎么走的

5 路引脚看电平
→
Get_KeyVal连数 3 次消抖
→
keyvalue[5]五格信箱（全局）
→
KEY_Scan取一格
→
KeyNum公告栏（全局）

然后 页面 / 电机 / 背光 各自路过时「看一眼」公告栏，自己决定要不要动

公告栏这个比喻很关键：KeyNum 是一张贴在墙上的便签，谁都能读，但没有人负责撕掉。只有下一轮的 KEY_Process() 会换上一张新便签（没按键时换成 0）。也就是说，「这条消息算不算已经被处理过」全靠主循环的执行顺序隐式保证。

4. 现在别扭在哪儿（六个地方）

A · 便签没人撕，同一条消息被看好几遍

大白话：有人按了一次，程序却当成按了好几次。

原工程主循环里有一句 uart3_at_sequence_main_loop_tick() → continue，一旦条件成立就跳过整轮的 KEY_Process()。但 KeyNum 还留着上一轮的值，页面、电机、背光照旧读到它：翻页连跳、背光一直被唤醒、停止键反复执行。

main.c:72–76 · Dispaly.c:199 / 248 / 339 / 502 · dc_motor.c:258 / 263 / 269

B · 秒表被拿走了，「数三下」不再等于 30 毫秒

大白话：消抖本来是「每隔 10ms 数一下，数满 3 下算按下」，现在变成「主循环每跑一圈数一下」。

原工程由 TIM2 的 5ms 中断每两次置一次 flag10ms，代码只在这个节拍里数数，所以 3 次 = 30ms。新工程把 if (flag10ms == 0) return; 这两行注释掉了，于是消抖时间跟着主循环速度变：现在 main.c 是空的，一圈可能几十微秒，抖动根本滤不掉；等以后把屏幕、4G、EEPROM 加进来，一圈又突然变慢。同一个按键，改前改后手感不一样，还很难复现。

qibiji_zxl/HARDWARE/KEY/key.c:63–66（被注释） · 原工程 HARDWARE/TIMER/timer.c:227–230

C · 「按一次只报一次」其实是巧合，长按会自己再报

大白话：代码里有个「是否已经松开」的开关，但它从头到尾没被关过，等于摆设。

真正让一次按下只报一次的，是计数器被卡在 3 这个巧合：数到 3 时写一次事件。可卡住之后下一次又 ++ 变成 4，之后一路加到 255 溢出回 0，再数到 3 就又报一次。原来 10ms 一个节拍，大约每 2.5 秒自动重复一次；配合 B（节拍被注释、采样快了几十倍），就会退化成连发。

key.c:60（key_up 初值 1、从未置 0） · key.c:77–82 等 5 处相同的计数写法

D · 五个键写了五遍几乎一模一样的代码

大白话：90 行里只有键名和引脚不同。

每个键各配一个计数器，还要在每个分支里手动把另外 4 个计数器清零。想改一条规则（比如消抖改成 5 次）就得改 5 处，漏一处行为就不一致。这类代码最适合换成「一张引脚表 + 一个循环」。

key.c:68–147，五个 else-if 分支

E · 名字和面板对不上，一个键身兼数职

大白话：读代码时得先在脑子里做一次「KEY_ENTER 其实是 STOP 键」的翻译。

见第 2 节的对照表。更麻烦的是物理键和业务动作被焊死在一起：STOP 键在电机里是「停止」，在设置页里是「确认 / 下一位」，在浏览页里是「回首页」。按键模块不该替主程序做这个判断。

F · 夹带了不该放在这儿的东西

  • KeyLed_Ctl() 控制的是面板指示灯，被电机文件调用，却写在 key.c 里。新工程把它的实现注释了，但 key.h 第 22 行还声明着 —— 谁一调用就会链接报错。
  • key_local_remote_change、key_setting_change 两个变量全工程没有任何地方用，是遗留的空壳。
  • keyvalue[5]、KeyNum 都是全局变量，任何文件都能改，出了问题很难查是谁改的。

5. 名词小词典

上一轮回答里那些词，换成大白话是这个意思：

词大白话
消抖按下瞬间电平会抖几下，连着确认几次才算真按了，避免一次按被当成好几次
时基 / tick一个固定的节拍器，比如每 10ms 响一下，大家按它的节奏干活
全局广播消息贴公告栏，谁都读，没人负责撤 → 容易被重复读
接口 / 契约模块对外只开一个窗口，别人只能通过这个窗口拿数据，不许翻墙进屋
状态机把「松开 → 疑似按下 → 确认按下 → 一直按着 → 松开」写成几个明确的状态，而不是靠一堆计数器互相猜
表驱动5 个键的引脚写成一张表，用一个循环处理，代替 5 份重复代码
悬空声明头文件说「有这个函数」，实际却没写实现，一调用就报错
static把变量锁在模块内部，外面看不见也改不了

6. 打算改成什么样

把现在「一个公告栏」拆成三个各司其职的角色：

  • 节拍员（一个 10ms 定时器）：只负责每 10ms 敲一下，不干别的。
  • 按键模块 / 门房：只在鼓点上采样，用状态机判定，把「按了哪一颗」投进自己的小信箱（模块私有的事件队列）。
  • 主程序 / 前台：调 KEY_Pop() 取一张纸条，取走即清，再按当前页面决定分发给页面、电机还是背光。
10ms 节拍固定节奏
→
KEY_Tick采样 + 状态机
→
私有队列static，外面碰不到
→
KEY_Pop取走即清
→
main按页面分发

    Get_KeyVal();        // 写 keyvalue[5]

对外只留三个函数

// key.h —— 别人能看到的全部内容
typedef enum {
    KEY_NONE = 0,
    KEY_UP, KEY_DOWN, KEY_STOP, KEY_SET, KEY_CANCEL  // 用面板丝印命名
} key_code_t;

void       KEY_Init(void);   // 初始化引脚
void       KEY_Tick(void);   // 只在 10ms 节拍里调用
key_code_t KEY_Pop(void);    // 取走一个事件，没有就返回 KEY_NONE

键码用物理键名（STOP / SET / CAN），「这一键在设置页是不是确认」由页面自己判断。要不要长按连发，做成明写的配置项，不再靠计数器溢出这种副作用。

7. 对照表与落地顺序

项目现在改后
事件怎么交出去全局 KeyNum，谁都能读KEY_Pop() 返回值，取走即清
谁来分发各模块自己读main 按当前页面显式分发
消抖时间3 圈主循环，会漂移3 × 10ms = 30ms，固定
一次按下报几次靠计数巧合，长按约 2.5s 会自动重复状态机明写，长按行为可配置
五个键的代码5 份几乎相同的分支一张引脚表 + 一个循环
键名LEFT / RIGHT / ENTER（抄模板）STOP / SET / CAN（跟丝印一致）
模块内部状态全局可写全部 static
LED 控制塞在 key.c，头文件还留着悬空声明移到 LED 模块

动手前要记住的两件事

  1. 新工程 USER/main.c 现在还是空的 while(1)，连 KEY_Init() 都没调用 —— 按键代码目前「编译得过、跑不起来」，正好趁没接线先定接口。
  2. 新工程还没有定时器模块，需要补一个 10ms 时基。别用 SYSTEM/delay/delay.c 的 SysTick：delay_us/ms 会反复重配它的计数值，拿它当节拍会互相踩。用独立的 TIM 更稳。

落地顺序：① 定接口（KEY_Init / KEY_Tick / KEY_Pop）→ ② 补 10ms 时基 → ③ 用状态机重写并顺手修掉 A/B/C → ④ 改键名、清掉死变量和悬空声明。前两步定了后面所有模块怎么接，先做完就不会返工。
