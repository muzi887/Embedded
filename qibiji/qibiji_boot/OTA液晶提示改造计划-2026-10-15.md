# qibiji_boot 液晶 OTA 错误提示改造计划

> 状态：**已实施（2026-10-15）**　拟定日期：2026-10-15
> 实施结果见文末「6. 实施与验证记录」。
> 适用工程：`D:\huanghe\qibiji_boot`（BOOTV10）
> 目标：OTA 失败时在 LCD 上**显示出错类型**并**停留 3 秒**再跳应用，现场不需要串口就能看出失败原因。
> 本次不做：背光改动、过程提示（"重试中/等联网"）、错误写 EEPROM、失败上报平台、正常路径额外延时。

## 1. 背景与现状（已核实）

文案与调用映射（`HARDWARE/Lcd12864/Dispaly.c`，GB2312 字模 + 液晶自带汉字库，2 字节/字）：

| 函数 | 实际显示 | 位置 | 调用点 |
|---|---|---|---|
| `ota_step1()` | 在线升级 / 连接服务器中 | 第1、2行 | `main.c` 开启升级标志后进 OTA |
| `ota_step2()` | 连接成功 + 申请最新固件 | 第2、3行 | `main.c` 收到回包 |
| `ota_step3()` | 开始更新 | 第3行 | 下载开始 |
| `ota_step4()` | 无新版本 | 第3行 | `NO_UPDATE`（沿用 1s 后跳） |
| `ota_step5()` | **更新出错** | 第3行 | 6 处错误分支 |
| `ota_step6()` | 更新完毕 | 第3行 | 下载完成 |
| `ota_step7()` | 清屏 | — | 复位前 |

问题清单：

- **F1 背光可能没亮**：`Lcd_Gpio_Init()` 写 `BackLight = 1; // 关闭背光`，`BLight_Ctrl()` 同值却注释"打开背光"且**无调用点**（本次不动，见"假设"）。
- **F2 引导阶段错误液晶无提示**：`BootLoader_Brance()`、`AT24CXX_ReadOTAInfo()` 都早于 `Lcd_Gpio_Init()`，护栏/校验/自愈/EEPROM 错误只在串口可见。
- **F3 "更新出错"停留≈0**：6 处 `ota_step5()` 后基本立刻 `JumpToApp()` 离开 B 区，应用接管屏幕。
- **F4 错误不分类**：所有失败都显示同一句"更新出错"。
- **F5 过程提示缺失**：等 AT / 等联网 / 重发 / CRC 重试期间界面静止。
- **F6 收尾一闪而过**：`ota_step6()` → 1s → `ota_step7()` 清屏 → 0.5s → 复位；且 `ota_step7` 在 `Display.h` **无声明**（隐式声明）。
- **F7 无"升级已关闭"提示**：关闭升级标志后直接跳应用，现场看不出该设备不再检查更新。
- **F8 初始化不完整**：正式代码**从未调用 `LCDInit()`**，只在 `ota_step1/7` 补了 `WRCommandH(0x30)`。
- **F9 命名与文案错位**：`ota_stepN` 编号与文字不对应，联调易误读。
- **F10 失败无落库/上报**：`cjson_pub_putError()` 只在下载成功时调用且固定发 `success`，平台只有成功记录。

## 2. 实施内容

### 2.1 新增"错误类型"文案与显示入口

- 复用第 3 行"更新出错"（`step6`），新增**第 4 行（DDRAM 0x98）**类型行；新增 API `void ota_show_error(uint8_t kind)` 统一完成"第1行标题 + 第2行清空 + 第3行更新出错 + 第4行类型"。
- 类型宏与文案（每行 8 个 GB2312 汉字，16 字节数组）：

| kind 宏 | 文案 | GB2312 数组 | 触发点 |
|---|---|---|---|
| `OTA_ERR_NET` | 网络连接超时 | `0xCD,0xF8,0xC2,0xE7,0xC1,0xAC,0xBD,0xD3,0xB3,0xAC,0xCA,0xB1,0x20,0x20,0x20,0x20` | AT 无应答 60s、等待上线超时 |
| `OTA_ERR_TIMEOUT` | 请求超时 | `0xC7,0xEB,0xC7,0xF3,0xB3,0xAC,0xCA,0xB1,0x20×7` | 请求超时重试超限 |
| `OTA_ERR_LINK` | 连接中断 | `0xC1,0xAC,0xBD,0xD3,0xD6,0xD0,0xB6,0xCF,0x20×8` | 升级中掉线超限 |
| `OTA_ERR_DATA` | 数据校验失败 | `0xCA,0xFD,0xBE,0xDD,0xD0,0xA3,0xD1,0xE9,0xCA,0xA7,0xB0,0xDC,0x20×4` | CRC 超限、接收错误超限 |
| `OTA_ERR_IMAGE` | 固件包无效 | `0xB9,0xCC,0xBC,0xFE,0xB0,0xFC,0xCE,0xDE,0xD0,0xA7,0x20×5` | A2 镜像头非法、A1/A2 均无效 |
| `OTA_ERR_VERIFY` | 写入校验失败 | `0xD0,0xB4,0xC8,0xEB,0xD0,0xA3,0xD1,0xE9,0xCA,0xA7,0xB0,0xDC,0x20×4` | 搬运 memcmp 失败、自愈校验失败 |
| `OTA_ERR_SIZE` | 固件大小错误 | `0xB9,0xCC,0xBC,0xFE,0xB4,0xF3,0xD0,0xA1,0xB4,0xED,0xCE,0xF3,0x20×4` | 护栏1 `OTA_size` 非法 |
| `OTA_ERR_EEPROM` | 存储异常 | `0xB4,0xE6,0xB4,0xA2,0xD2,0xEC,0xB3,0xA3,0x20×8` | 24C02 自检失败（OTA 关闭） |

- 同时补 `Display.h` 中缺失的 `void ota_step7(void);` 声明。

### 2.2 错误提示"停留 3 秒再跳"

- 新增 `static void OtaReportErrorAndExit(uint8_t kind){ ota_show_error(kind); delay_ms(3000); JumpToApp(); }`。
- 把主循环 6 处 `ota_step5();` 替换为对应的 `OtaReportErrorAndExit(OTA_ERR_*)`；原有 `printf` 与 `delay_ms(200)` 保留。
- `JumpToApp()` 因 A1 不可运行而返回时，继续留在 OTA 循环（行为不变）。

### 2.3 引导阶段错误也要能显示

- 新增全局（`boot.c` 定义、`boot.h` 声明）：`u8 g_ota_lcd_err = 0;`（0=无，否则 `OTA_ERR_*`）、`u8 g_ota_lcd_hold = 0;`（1=显示后停 3s 再跳；0=只显示不等）。
- `BootLoader_Brance()` 的 5 个错误路径：把"立即 `LOAD_A()`"改为设置 `g_ota_lcd_err` + `g_ota_lcd_hold=1` 后 `return`（EEPROM 侧 flag/清版本动作不变）。
- `reg.c` EEPROM 自检失败：设 `OTA_ERR_EEPROM` 且 `hold=0`（避免每次上电都慢 3 秒）。
- `main.c` 在 `CLEARGDRAMH(0x00)` 之后、`UPDATE_flag` 判断之前：
  `if (g_ota_lcd_err) { ota_show_error(g_ota_lcd_err); if (g_ota_lcd_hold) { delay_ms(3000); g_ota_lcd_err = 0; JumpToApp(); } else g_ota_lcd_err = 0; }`

### 2.4 Flash 预算

- B 区已扩容为 56KB（`Max: 0xE000`），当前载入区 40,688B → 余量约 **16,656 字节**，本改造（文案 8×16 + 显示/助手/全局 ≈ 250~290B）**无需腾空间**。
- 若将来仍紧张，按序腾：① 删死代码（`Lcd_DisplayString` 184B + `_Default` 16B + `loading` 14B + `code[][24]` 24B）；② 合并引导期串口日志；③ 精简重复 `printf` 文案。不得放宽 IROM 上限、不得关闭 MicroLIB、不得改优化等级（仍 -O0）。

## 3. 接口/约定

- 新接口（仅设备内部）：`void ota_show_error(uint8_t kind)`、`OTA_ERR_*`（0–7）、`extern u8 g_ota_lcd_err/g_ota_lcd_hold`、补声明的 `ota_step7()`。
- 屏幕布局：第1行"在线升级"、第2行清空、第3行"更新出错"、第4行错误类型；正常流程文案与刷新时机不变。
- 不改 OTA 协议、不改 EEPROM 布局、不改分区与 Keil 设置。

## 4. 测试计划

1. **编译**：Keil 全量 rebuild → 0 Error/0 Warning；载入区 ≤ `0xE000`。
2. **正常流程回归**：连接服务器中 → 连接成功/申请最新固件 → 开始更新 + 进度条 → 更新完毕 → 复位后跑新程序。
3. **8 类错误逐个可见（各停 3 秒）**：拔 4G/天线→网络连接超时；停平台→请求超时；升级中拔天线→连接中断；注入 CRC 错误→数据校验失败；上传 `.hex`→固件包无效；破坏 A2 但保留镜像头→写入校验失败；改写 EEPROM `OTA_size`→固件大小错误；断开 24C02→存储异常（不停留）。
4. **引导阶段提示验证**（关键）：`固件包无效 / 写入校验失败 / 固件大小错误` 发生在 LCD 初始化之前，必须确认上电后**先亮出提示再跳应用**（验证 pending 机制）。

## 5. 假设与未决

- 背光极性/点亮时机本次不动；若现场屏幕偏暗导致仍看不清，属 F1，需另行确认 PA0 极性与点亮时机。
- 3 秒停留只在**错误**路径；"无新版本"仍 1 秒、"更新完毕"仍 1 秒。
- 不改 `ota_stepN` 命名，仅在 `Display.h` 加注释说明"step5=出错、step6=完毕"的错位。

## 7. 追加变更（2026-10-15）：放弃升级改为「关闭升级标志 + 真复位」

按后续确认的方案，`main.c` 的 `OtaReportErrorAndExit()` 已更名为 **`OtaGiveUpAndReboot(kind)`**，6 处调用点统一改为：

```
ota_show_error(kind) → OtaCloseUpdateGate()（先关闭升级标志：写 EEPROM 240/1B=0）
   → delay_ms(1500) → IWDG_Feed() → delay_ms(1500) → NVIC_SystemReset()
```

- 为什么"先关闭升级标志再延时"：复位前把 `UPDATE_flag=0` 落盘，复位后 `main` 直接 `JumpToApp()` 跑 A1 应用，不会再进 OTA 状态机造成复位循环（这正是当初把 `NVIC_SystemReset()` 注释掉的原因）。
- 复位时 `main()` 会执行 `GM4G_Init()`（内含 PA1 复位脉冲）→ 4G 模组也硬复位一次；再次升级需平台经 A1 应用重新开启升级标志。
- 编译 0 Error / 0 Warning；反汇编核对顺序正确、`OtaCloseUpdateGate` 写 `0xf0`(240)/长度 1 ✓；`JumpToApp()` 仍被使用（pending 提示路径、升级标志为 0 的启动路径），无死代码。
