## 0. 一页速览：它到底是什么

**一句话**：这是 STM32F103VET6 上一个「引导 + 联网升级 + 跳转」三合一的 **IAP BootLoader**，本身不含闸门/电机等业务功能，业务在 A1 应用工程里。它只干两件事——把新固件弄进 Flash，然后把 CPU 交给应用。

### 0.1 四个关键数字

| 项 | 值 | 出处 |
|---|---|---|
| Flash 分区 | B 引导区 `0x08000000`，56KB（28 页）| `HARDWARE/BOOT/boot.h:14-20` |
| A1 运行区 | `0x0800E000`，200KB（100 页）| `boot.h:19-20` |
| A2 下载暂存区 | `0x08040000`，200KB（100 页）| `boot.h:22-24` |
| 固件上限 | 200KB（A1/A2 各 100 页 × 2KB）| `boot.h:68-75` 编译期断言 |
| EEPROM | AT24C02，`OTA_ADDR=200`（结构体 44B）、重试计数 244、检测标志 250 | `boot.h:29,58`、`24cxx.h:24` |
| 看门狗 | `IWDG_Init(4,1990)` ≈ 3.18s | `USER/main.c:131` |
| 单包固件 | `BYTESIZE 512` 字节 + 2 字节 CRC16 | `gprs.h:31` |

Keil 工程 `USER/BOOTV10.uvprojx:275-276` 的 IROM1 = `0x08000000 / 0xE000`，与 B 区严格一致；`boot.h:68-75` 用负数组长度断言把「A1 紧接 B、A2 紧接 A1、A2 末不越片尾、A1/A2 各 200KB、B=0xE000」全部锁死，改分区会**编译期报错**。

### 0.2 上电的三条分支（`main.c:75-129`）

```text
上电 → delay/NVIC → USART1(调试) + USART2(4G) → 读 EEPROM → BootLoader_Brance()
  │
  ├─ ① OTA_flag != A1A1A1A1（A2 里有待安装固件）
  │     → 校验 size/镜像头 → Cal_Block → Update_A1 逐页搬 A2→A1
  │     → memcmp 比对通过 → 写 flag=A1、关 UPDATE_flag → LOAD_A(A1)   [boot.c:127-179]
  │
  ├─ ② flag=A1 但 A1 镜像头非法（烧写器整片擦除、EEPROM 没擦）
  │     → A2 仍有效则重搬（最多 3 次）→ 否则清 OTA_ver 强制重下   [boot.c:182-228]
  │
  └─ ③ 回到 main：UPDATE_flag == 1 ?
        ├─ 否 → JumpToApp() = LOAD_A(0x0800E000)   （IWDG 此时还没启动）
        └─ 是 → ota_step1() → IWDG_Init → 进 OTA 状态机大循环
```

`LOAD_A()`（`boot.c:247-263`）只做一件事链：校验栈顶落在 `0x20000000~0x2000FFFF` → `MSR_MSP` 设主栈 → 取 `addr+4` 复位向量当函数指针 → `BootLoader_Clear()`（仅 `USART_DeInit(USART1/2)` + LCD 清屏）→ 跳过去。**SP 非法时只打印 `load progarm A is fail` 并返回**，落回 OTA 状态机继续重试，这是自愈入口。

### 0.3 升级链路一句话

4G 模组（USART2 @115200，模块内部维护 MQTT）↔ 服务器，设备主动请求、服务器才应答：
`putVersion` 报版本 → 回执带 `{size, version, upgrade}` → `getFirmware{offset:N}` 逐包请求 → 每包回执是 **`7,{JSON} + 512B 数据 + 2B CRC16`（JSON 与二进制同帧）** → CRC 校验通过写 A2 → 末包把 `OTA_ver/size/flag=A2` 落盘 EEPROM → `NVIC_SystemReset()` → 下次上电走上面分支 ① 生效。


## 3. 文档完全没记的新机制（都在 10-15 之后加入）

### 3.1 掉线续传：从「从 0 重来」变成「接着在途包」

总纲写的是「进度不落盘、中途复位一切从 offset 0 重来」。当前 `main.c` 的 `OTA_STATE_ONLINE` 有两个新分支（`main.c:222-241`）：

- `gprs_rx_defer_pending()`：掉线重连窗口里若已经收到平台的 `putVersion` 回包，先暂存进 `s_defer_buf[512]`（`gprs_rx.c:34-42,366-378`），重连后直接消费，**不重新协商、不重发 putVersion**。有长度钳位、忙时丢弃、会话复位清零。
- `gprs_download_pending()` + `gprs_resend_last_request()`：下载会话在途时，重连后**重发在途的 offset 请求**（`gprs_tx.c:200-208`，带 `g_last_valid` 保护），不从 0 开始。
- `link_loss_count`：会话级掉线预算 5 次（`main.c:68-69,143-152,322`），超限才放弃；新一轮下载会话清零。

配套还有整帧重组 `gprs_rx_take_frame()`（`gprs_rx.c:169-277`）与缓冲溢出重同步（`:191-200`），不再假设「一次 UART 帧 = 一条完整 MQTT 消息」。

### 3.2 分包校验从「几乎裸奔」变成有闸门

- `count` 恢复 512 分块：`size/512 (+1)` + `remaining` 记末包长度（`gprs_rx.c:552-562`），完成条件 `Offset == count-1`（`:716`）语义自洽。
- **序号闸门**：`Offset != s_dl_expected_offset` 时拦下，重请求期望序号（`:624-635`、`:701`），乱序/重复包不再静默错位。
- 长度闸门：`size ≤ 200KB`（`:546`）、`0 < Size ≤ 512`（`:639`）、累计长度不超声明大小（`:646`）、末包累计字节数必须等于 `OtaParas.size`（`:720`）。
- 新增返回码 `GPRS_RX_ERR_PACKET_SIZE/-43`、`LENGTH_OVERFLOW/-44`、`SEQ_RETRY_EXCEEDED/-45`（`gprs.h:64-66`）。

### 3.3 其余新增

| 机制 | 说明 | 位置 |
|---|---|---|
| `g_ota_lcd_err` / `g_ota_lcd_hold` | 引导/EEPROM 阶段 LCD 还没初始化，先登记错误码，等 `CLEARGDRAMH()` 后补显示；`hold=1` 停 3s 再跳应用，`0`（持久性错误）只显示不等 | `boot.h:95-100`、`reg.c:57-58`、`main.c:103-116` |

## 4. 当前仍然成立的风险（未修，按影响排序）

### 4.1 `STMFLASH_Write` 跨扇区地址单位错误 —— 会静默损坏镜像

`HARDWARE/STMFLASH/stmflash.c:73` 原文：

```c
pBuffer+=secremain;  	// 指针偏移（单位：半字，正确）
WriteAddr+=secremain;	// 写地址偏移（单位应是字节，却按半字加了）
```

`secremain` 的单位是**半字**（`:49`），而 `WriteAddr` 是**字节地址**（`:44/:46` 与 `STMFLASH_Write_NoCheck` 里 `WriteAddr+=2` 都按字节）。一次写入跨 2KB 扇区边界、且下一扇区为空白（全 `0xFFFF`）时，第二段数据会写到偏小 `secremain` 字节的位置。A2 首次下载是全 `0xFF`，每 4 个 512B 包就有一个跨扇区，属于**必现路径**；分包 CRC 只覆盖数据本身，检测不到，问题要到运行新固件时才暴露。

> 方向：`WriteAddr += secremain * 2;` 并补跨扇区回读校验。（**本文未改代码**）

### 4.2 跳转前未重定位向量表、外设状态残留

`LOAD_A()` 里 `vtor = SCB->VTOR;` **只打印不写回**（`boot.c:253-254`），本工程 `system_stm32f10x.c:128` 的 `VECT_TAB_OFFSET = 0x0`，指向 B 区向量表。A1 应用必须在自己的 `SystemInit` 里设 `0x0E000`（总纲 §8-9 称 A1 工程已确认如此），否则运行期任何中断都会跳回 B 区。

`BootLoader_Clear()`（`boot.c:269-278`）只复位 USART1/USART2 和清屏，DMA1_CH5/CH6、EXTI9_5、SysTick、IWDG、LCD GPIO 全部保持 B 区状态——`main.c:38-41` 的注释也明确承认了这一点。特别注意：**「无需升级 → JumpToApp()」发生在 `IWDG_Init()` 之前**（`main.c:128` vs `:131`），此时看门狗没开；但**「放弃升级 → `OtaGiveUpAndRunApp()`」时 IWDG 已经启动且无法关闭**，A1 必须在 3.18s 内开始喂狗。两条跳转路径对外设的要求不一样。

### 4.3 其它

- **在线判断**：`gprsonlineflag`（`4G.c:9`）无初值，`GM4G_Init()` 不读 PC5 电平，只在 EXTI 双沿跳变时更新。上电时模块已在线且无跳变 → 标志恒 0 → 约 40s 后放弃升级。
- **解析失败返回 0 仍被当正常**（`gprs.h:48` + `main.c:308-311`）：收到垃圾帧会不断清零超时/重试计数，只有「完全没数据」(-100) 才计时。
- **无整包校验**：`OtaPara.signMethod/dProtocol/streamId`（`gprs.h:73-75`）至今未被使用；平台侧 `FileMd5` 字段可作为落点。
- **`boot.h:102-104` 注释与代码不一致**（见 §1.1 末）。
- 跳转直跳路径只查栈顶 SP，未校验复位向量；镜像头校验（`OtaImageValidAt`）只在搬运/自愈路径调用。

## 5. 结论与建议

1. **这个工程的骨架没变**：B/A1/A2 三分区、EEPROM 标志驱动搬运、4G MQTT 分包下载、复位后生效——总纲 §0~§6 的整体描述今天仍然可读。
2. **但风险清单和「放弃升级」章节已经不能当依据**：P0-2、P0-3、P1-9 已修，§6.5.6 断点续传已反转，§10.6 方案整个被推翻。当前 `gprs_rx.c` 1119 行，比文档基线多出 314 行，全是健壮性相关逻辑。
3. **真正还悬着的是三件事**：`stmflash.c:73` 的跨扇区地址 bug（会静默写坏 A2 镜像）、跳转前 VTOR/外设归属约定、整包完整性校验缺失。前两项在 OTA 路径上是必现或高风险路径。
