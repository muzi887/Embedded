# bootV10 BootLoader 说明

本文说明：**BootLoader 是什么**，以及在本工程（bootV10）里它具体做什么。详细 OTA 流程见 [OTA说明.md](./OTA说明.md)。

---

## 1. 一句话定义

**BootLoader（引导加载程序）** 是 MCU 上电/复位后**最先运行**的一段小程序。它不负责日常业务（电机、界面等），而是负责：

- 决定接下来跑哪份固件
- 必要时完成固件搬运/升级
- 再把 CPU 控制权交给真正的应用程序

可以把它理解成：开机时的「门卫 + 换装工」——先检查要不要换新程序，再打开通往应用的门。

---

## 2. 为什么需要 BootLoader

若整片 Flash 只有一份应用固件：

- 在线升级时只能直接改正在运行的区域，断电或写坏就变「砖」
- 无法在保留旧程序可运行的前提下安全下载新程序

因此本工程把 Flash 分成独立区域：

| 角色 | 分区 | 作用 |
|------|------|------|
| BootLoader 自身 | B 区 | 固定驻留，负责引导与升级逻辑 |
| 正式应用 | A1 区 | 平时真正运行的业务固件 |
| 下载暂存 | A2 区 | OTA 时先写入这里，验证/完成后再覆盖到 A1 |

应用固件可以反复升级；BootLoader 平时不更新，保证设备始终有一条可控的启动路径。

---

## 3. 本工程中的 BootLoader

### 3.1 它是什么

本仓库 `bootV10` **本身就是 BootLoader 工程**，运行在 STM32F10x（如 F103VET6 / VCT6）上：

- 链接/烧录起始地址：`0x08000000`（Flash 开头，B 区）
- 占用约 40KB（20 页 × 2KB）
- 入口在 `main.c`：初始化外设 → 读 EEPROM → 分支判断 → 跳转应用或进入 OTA

应用工程（A1）需单独编译，且起始地址应对齐 `0x0800A000`，与 Boot 分区错开。

### 3.2 Flash 布局

```text
0x08000000  ┌─────────────────────┐
            │  B 区 · BootLoader  │  ~40KB
0x0800A000  ├─────────────────────┤
            │  A1 区 · 应用主区   │  ~200KB  ← 平时运行这里
0x0803C000  ├─────────────────────┤
            │  A2 区 · 下载备份区 │  ~200KB  ← OTA 先写这里
            └─────────────────────┘
```

定义见 `HARDWARE/BOOT/boot.h`：`ST32_A1_SADDR`、`ST32_A2_SADDR` 等。

### 3.3 核心职责（三件事）

1. **分支与生效**（`BootLoader_Brance`）  
   读 EEPROM 里的 `OTA_flag`：若为 `OTA_A2_FLAG`，说明 A2 有新固件，先把 A2 整包拷到 A1，再改回 `OTA_A1_FLAG`。

2. **跳转到应用**（`LOAD_A`）  
   检查 A1 向量表栈指针是否合法 → 设置 MSP → 清 Boot 侧外设 → 跳到 A1 复位向量，之后 CPU 只跑应用代码。

3. **可选的联网升级**（`UPDATE_flag == 1`）  
   不立刻跳 A1，而是用 4G/MQTT 从服务器下载固件到 A2；下载完成后写标志并复位，下一轮再由 Boot 完成 A2→A1。

`UPDATE_flag == 0` 时：做完分支判断后直接 `LOAD_A(A1)`，Boot 几乎「一闪而过」。

## 4. 上电后大致流程

```text
复位 / 上电
    │
    ▼
运行 B 区 BootLoader（本工程）
    │
    ├─ 读 EEPROM：OTA_flag / UPDATE_flag / 版本 / 大小
    │
    ├─ OTA_flag 不是 A1？
    │      └─ 是 → A2 搬运到 A1 → 写回 A1 标志
    │
    ├─ UPDATE_flag == 1？
    │      ├─ 是 → 联网 OTA（下载到 A2，成功后复位）
    │      └─ 否 → LOAD_A(A1) 进入应用
    │
    ▼
应用在 A1 持续运行（Boot 不再占用 CPU）
```

跳转成功后，业务逻辑与日常功能都在 A1 固件里；只有再次复位，才会重新进入 BootLoader。

---

## 5. 和「应用固件」的区别

| | BootLoader（本工程） | 应用固件（A1） |
|--|---------------------|----------------|
| 存放位置 | `0x08000000` 起 | `0x0800A000` 起 |
| 何时运行 | 每次上电最先跑 | Boot 跳转之后 |
| 主要任务 | 引导、换区、OTA | 产品业务功能 |
| 是否常升级 | 一般不随业务改 | OTA 频繁更新的对象 |
| 失败影响 | 升级失败仍可尝试回 A1 | 损坏时依赖 Boot 保护路径 |

没有 BootLoader，芯片复位后只能从固定地址跑单一镜像；有了它，才能在「不拆机烧录」的前提下安全换应用。

## 6. 关键代码位置

| 文件 | 作用 |
|------|------|
| `docs/USER/main.c` | Boot 入口与 OTA 状态机主循环 |
| `HARDWARE/BOOT/boot.c` / `boot.h` | 分区宏、`BootLoader_Brance`、`LOAD_A`、`Update_A1` |
| `HARDWARE/REG/reg.c` | EEPROM 中 OTA 信息读写 |
| `HARDWARE/GPRS/*` | 联网下载（Boot 内 OTA 路径） |
| `HARDWARE/STMFLASH/stmflash.c` | 向 A1/A2 写 Flash |

---

## 7. 小结

- **概念上**：BootLoader = 上电最先运行、负责引导与安全换固件的小程序。  
- **本工程上**：bootV10 就是这块 BootLoader，占 Flash B 区；通过 A1/A2 双区 + EEPROM 标志完成启动分支与 OTA 生效。  
- **日常运行**：多数时候 Boot 很快把控制权交给 A1；只有需要升级或刚下完新固件时，才会在 Boot 里停留更久。

更细的升级协议与状态机，见 [OTA说明.md](./OTA说明.md)；完整模块梳理见 [程序功能及流程文档.md](./程序功能及流程文档.md)。
