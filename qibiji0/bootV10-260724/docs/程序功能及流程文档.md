# STM32 BootLoader程序功能及流程文档

## 1. 项目概述

本项目是一个基于STM32F10x系列微控制器的BootLoader（引导加载程序）系统，主要功能是实现OTA（Over-The-Air）固件更新和应用程序跳转。系统采用双区备份机制：联网下载写入A2备份区，复位后由BootLoader将A2搬运到A1再跳转运行，保证更新过程可恢复。

### 1.1 硬件平台
- **MCU型号**: STM32F103VET6 / STM32F103VCT6
- **Flash容量**: 512KB / 256KB
- **RAM容量**: 64KB / 48KB
- **Flash页大小**: 2KB

### 1.2 主要功能模块
- BootLoader引导与A2→A1搬运
- 4G/GPRS联网OTA（MQTT + JSON/二进制分包）
- EEPROM存储（24C02，OTA元信息）
- LCD12864显示与OTA进度条
- 看门狗保护
- LED / 直流电机控制接口
- DS1302时钟（通信时间戳等）

## 2. Flash存储分区规划

### 2.1 分区布局（以512KB Flash为例）

| 分区名称 | 起始地址 | 页数 | 大小 | 用途 |
|---------|---------|------|------|------|
| Boot区(B) | 0x08000000 | 20页 | 40KB | BootLoader程序区 |
| A1区 | 0x0800A000 | 100页 | 200KB | 应用程序主区（运行区） |
| A2区 | 0x0803C000 | 100页 | 200KB | 应用程序备份区（下载区） |

### 2.2 地址定义

```c
#define ST32_FLASH_SADDR    0x08000000    // Flash起始地址
#define ST32_PAGE_SIZE      2048          // Flash页大小（2KB）
#define ST32_B_PAGE_NUM     20            // Boot区页数（40KB）
#define ST32_A1_SADDR       0x0800A000    // A1区起始地址
#define ST32_A2_SADDR       0x0803C000    // A2区起始地址
```

### 2.3 OTA标志定义

```c
#define OTA_A1_FLAG        0xA1A1A1A1    // A1区固件有效/已生效
#define OTA_A2_FLAG        0xA2A2A2A2    // A2区有新固件，复位后需搬运到A1
#define OTA_ADDR           200           // EEPROM中OTA信息起始地址
#define BYTESIZE           512           // OTA单包二进制数据长度
```

## 3. 核心数据结构

### 3.1 OTA信息结构体（持久化到EEPROM）

```c
typedef struct {
    u32 OTA_flag;           // OTA_A1_FLAG / OTA_A2_FLAG
    u8  OTA_ver[32];        // 当前固件版本号
    u32 OTA_size;           // 固件总字节数
    u8  UPDATE_flag;        // 0：不走联网OTA，直接跳A1；1：进入联网OTA流程
} OTA_InfoCB;
```

**存储位置**: EEPROM地址200（`OTA_ADDR`）  
**读写入口**: `AT24CXX_ReadOTAInfo()` / `AT24CXX_Write()`；默认参数可由 `paraToEeprom()` 写入一次（生产初始化后通常注释掉）。

### 3.2 更新缓冲区结构体（A2→A1搬运）

```c
typedef struct {
    u8  Updatabuff[ST32_PAGE_SIZE];  // 更新缓冲区（2KB）
    u8  BlockNB;                      // 块数量
    u16 size;                         // 最后一块的半字数量（halfword）
} UpDataA_CB;
```

### 3.3 运行时OTA参数与状态

```c
// 服务器协商得到的下载参数（gprs.h）
typedef struct {
    u32  size;           // 固件总字节数
    char ver[32];        // 目标版本
    // ...
    u16  count;          // 当前实现中赋值为 size（总字节）
    u16  remaining;      // 末包剩余（历史字段）
} OtaPara;

// 主状态机（main.h）
#define OTA_STATE_WAIT_NET        0
#define OTA_STATE_ONLINE          1
#define OTA_STATE_SEND_VERSION    2
#define OTA_STATE_HANDLE_REPLY    3
#define OTA_STATE_REBOOT          4
#define OTA_STATE_AT_OK           5
#define OTA_STATE_MQTTCID_OK      6
```

下载上下文（`gprs_rx.c` 静态变量）：`s_dl_addr`、`s_dl_lastaddr`、`s_dl_last_offset`、`s_dl_crc_retry_cnt`。

## 4. 程序流程分析

### 4.1 主程序流程（main.c）

```
开始
  ↓
delay_init / NVIC_Configuration
  ↓
uart1_init(460800)          // PC调试
uart2_init(115200)          // 4G模块
  ↓
AT24CXX_Init / AT24CXX_ReadOTAInfo
ds1302_init
  ↓
BootLoader_Brance()         // 若OTA_flag!=A1，则A2→A1后跳转
  ↓
LED_Init / Lcd_Gpio_Init / GM4G_Init
  ↓
判断 UPDATE_flag
  ├─→ == 0：直接 LOAD_A(A1)，结束Boot联网流程
  └─→ == 1：显示ota_step1，进入OTA主循环
        ↓
      IWDG_Init(4,1990)
        ↓
      while(1)：喂狗 + gprs_rx_datas() + 状态机处理
```

### 4.2 BootLoader分支流程（BootLoader_Brance）

```
开始
  ↓
读取 OTA_Info.OTA_flag
  ↓
OTA_flag == OTA_A1_FLAG ?
  ├─→ 是：直接返回（由main决定是否联网OTA或跳A1）
  └─→ 否（通常为OTA_A2_FLAG）
        ↓
      Cal_Block()
        ↓
      Update_A1()           // A2 → A1 按页搬运
        ↓
      OTA_flag = OTA_A1_FLAG，写EEPROM
        ↓
      写入成功 → LOAD_A(A1)
```

说明：下载完成后固件在A2，标志为`OTA_A2_FLAG`；复位后由本函数完成生效。

### 4.3 联网OTA状态机（UPDATE_flag==1）

```
WAIT_NET
  ├─ 周期 At_init()，收到 OK → AT_OK
  ↓
AT_OK
  ├─ 等待 gprsonlineflag==1（PC5中断）→ ONLINE
  ├─ 长时间不上线 → 跳转A1（放弃本次OTA）
  ↓
ONLINE
  ├─ ota_step2（LCD：版本询问）→ SEND_VERSION
  ↓
SEND_VERSION
  ├─ cjson_pub_version() → HANDLE_REPLY
  ↓
HANDLE_REPLY（处理 gprs_rx_datas 返回值）
  ├─ NO_UPDATE        → ota_step4，跳转A1
  ├─ START_UPDATE     → ota_step3，进度条初始化，开始分包下载
  ├─ DOWNLOAD_CONTINUE → 继续收包写A2
  ├─ DOWNLOAD_DONE     → ota_step6/7，NVIC_SystemReset
  ├─ 超时/CRC超限/解析错误累计超限 → 跳转A1（保底运行旧固件）
  └─ 掉线 → 回退 WAIT_NET
```

### 4.4 分包下载与写A2（gprs_rx / cjson_download_reply）

```
收包格式：{JSON} + {Size字节bin} + {2字节CRC}
  ↓
长度检查（Size+2 ≤ message_len）
  ↓
CRC16_CCITT_FALSE 校验
  ├─ 失败：同offset最多重试5次，再请求该包
  └─ 成功：STMFLASH_Write 写入A2，更新进度条
        ↓
      非末包：cjson_pub_getbin(Offset+1)
      末包：更新 OTA_ver / OTA_size / OTA_flag=OTA_A2_FLAG → 写EEPROM
            → 返回 DOWNLOAD_DONE → 复位
```

### 4.5 应用程序跳转流程（LOAD_A）

```
开始
  ↓
读取目标地址的SP值
  ↓
验证 SP ∈ [0x20000000, 0x2000FFFF]
  ├─→ 是
  │     保存VTOR → MSR_MSP(SP) → 取复位向量(addr+4)
  │     → BootLoader_Clear() → 跳转应用
  └─→ 否：打印失败信息
```

### 4.6 A2→A1更新流程（Update_A1 / Cal_Block）

与历史逻辑一致：按页从A2读、写到A1；`Cal_Block` 根据 `OTA_size` 计算块数，最后一块按半字（16位）对齐写入。

## 5. 关键函数说明

### 5.1 BootLoader_Brance()
**功能**: 若EEPROM中`OTA_flag`不是`OTA_A1_FLAG`，将A2固件搬运到A1并生效后跳转  
**说明**: 不再在此处做版本查询；联网OTA由`main`中`UPDATE_flag`驱动

### 5.2 LOAD_A(uint32_t addr)
**功能**: 跳转到指定应用程序区  
**说明**: 校验栈指针、设置MSP、清理Boot资源后跳转

### 5.3 MSR_MSP(uint32_t addr)
**功能**: 汇编设置主栈指针MSP

### 5.4 Update_A1() / Cal_Block()
**功能**: A2→A1按页搬运；计算块数与末块半字数

### 5.5 BootLoader_Clear()
**功能**: 反初始化USART1/USART2，并复位LCD命令，释放Boot占用资源

### 5.6 AT24CXX_ReadOTAInfo() / paraToEeprom()
**功能**: 读OTA元信息；EEPROM异常时默认`OTA_A1_FLAG`与版本`1.0.0`  
**说明**: `paraToEeprom()` 可写默认`UPDATE_flag=1`，通常仅产线初始化调用一次

### 5.7 gprs_rx_datas() / cjson_pub_version() / cjson_pub_getbin()
**功能**: 解析4G接收数据；上报版本；按offset请求固件分包

### 5.8 gprs_resend_last_request() / gprs_download_context_reset()
**功能**: 超时重发上次请求；清零下载地址/offset/CRC重试计数

### 5.9 ota_step1~7 / progressbar_Init / ProgressBar_Update
**功能**: LCD提示OTA各阶段状态与下载进度

## 6. 通信接口

### 6.1 UART1
- **波特率**: 460800
- **用途**: PC调试打印

### 6.2 UART2
- **波特率**: 115200
- **用途**: 4G模块（AT / MQTT业务）
- **缓冲**: DMA接收缓冲约1024字节，JSON与bin同帧解析

### 6.3 IIC
- **用途**: EEPROM（24C02）
- **功能**: 存储OTA_flag / OTA_ver / OTA_size / UPDATE_flag

### 6.4 网络在线检测
- **信号**: `gprsonlineflag`（由`EXTI9_5_IRQHandler`根据PC5边沿更新）

## 7. 安全与容错机制

### 7.1 看门狗
- **类型**: IWDG
- **超时**: 约3.18s（分频4，重载1990）
- **要求**: 主循环定期`IWDG_Feed()`

### 7.2 双区备份
- **A1**: 当前可运行应用
- **A2**: OTA下载暂存；下载完成后置`OTA_A2_FLAG`，复位后搬运到A1
- **失败保底**: 超时/CRC超限/解析错误多次后`LOAD_A(A1)`，尽量回到旧固件

### 7.3 分包CRC
- 算法：`CRC16_CCITT_FALSE`
- 同offset最多重试5次，超限上报异常并由主循环处理

### 7.4 请求超时重发
- 无数据约3s（30×100ms）重发上次请求，最多5次，超限跳转A1

### 7.5 栈指针验证
- 跳转前检查目标SP是否在RAM合法范围，防止跳入无效镜像

## 8. 工作模式

### 8.1 正常启动（UPDATE_flag=0）
1. 上电初始化，读EEPROM  
2. 若`OTA_flag!=A1`，先完成A2→A1再跳转  
3. 否则直接`LOAD_A(A1)`

### 8.2 联网OTA（UPDATE_flag=1）
1. Boot分支处理完可能的A2→A1后返回  
2. AT握手 → 等待在线 → 上报版本  
3. 服务器`upgrade==1`且版本不同：分包下载写入A2  
4. 写EEPROM（`OTA_A2_FLAG` + 新版本/大小）→ 复位  
5. 再次上电由`BootLoader_Brance`搬运A2→A1并跳转新固件  
6. 无需升级：直接跳转A1

## 10. 注意事项

### 10.1 Flash
- 写入前按页擦除；半字写入；操作期间注意中断影响

### 10.2 跳转
- 跳转前`BootLoader_Clear()`；确认目标镜像SP合法

### 10.3 EEPROM
- OTA信息在地址200；结构体含`UPDATE_flag`，长度以`OTA_INFOCB_SIZE`为准
- `UPDATE_flag`需由业务/产线写入；`paraToEeprom()`默认置1但通常被注释

### 10.4 OTA接收缓冲
- 单帧处理缓冲约1024字节，服务端分包需与`BYTESIZE(512)`及缓冲上限匹配

### 10.5 看门狗
- 进入主循环后必须及时喂狗；OTA等待/重试路径中也有`delay`，需保证周期内喂狗

## 14. gprs_rx_datas 主要返回值

| 返回值 | 含义 |
|--------|------|
| `GPRS_RX_RET_NO_DATA` (-100) | 无新数据 |
| `GPRS_RX_RET_AT_OK` (5) | AT应答OK |
| `GPRS_RX_RET_NO_UPDATE` (1) | 无需升级 |
| `GPRS_RX_RET_START_UPDATE` (2) | 开始下载 |
| `GPRS_RX_RET_DOWNLOAD_CONTINUE` (4) | 单包写A2成功 |
| `GPRS_RX_RET_DOWNLOAD_DONE` (3) | 整包下载完成 |
| `GPRS_RX_ERR_CRC_RETRY_EXCEEDED` (-19) | CRC重试超限 |
| `GPRS_RX_ERR_PACKET_SHORT` (-42) | 包长度不足 |
| `GPRS_RX_ERR_EEPROM_WRITE` (-20) | EEPROM写入失败 |
| `<0` 其他 | JSON/解析等错误 |

## 15. 总结

本BootLoader当前实现包含：

1. **安全启动**: SP校验后跳转A1  
2. **联网OTA**: `UPDATE_flag`控制；AT→在线→版本协商→分包CRC→写A2  
3. **双区生效**: 下载完成置`OTA_A2_FLAG`并复位，Boot再A2→A1  
4. **状态持久化**: EEPROM保存标志、版本、大小、是否联网OTA  
5. **容错**: 超时重发、CRC重试、错误累计后回退跳转A1  
6. **人机反馈**: LCD阶段提示与下载进度条  
7. **看门狗**: 主循环喂狗防止死机  

更细的时序与调用链见同目录 `OTA固件升级流程梳理.md`。
