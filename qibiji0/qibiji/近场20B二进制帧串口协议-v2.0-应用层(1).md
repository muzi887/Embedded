## 1. 分层定位

### 1.1 本文范围

```text
┌─────────────────────────────────────────────────────────┐
│  物模型 / 产品规范（TSL）                                 │
│  参数 identifier、控件类型、取值范围、可见性               │
│  → 见 [物模型_v2.md](../../../TSL/物模型_v2.md)           │
├─────────────────────────────────────────────────────────┤
│  SBF-20 应用层（本文）                                    │
│  UTF-8 JSON；op=read/write；code/params；读/写分片语义    │
├─────────────────────────────────────────────────────────┤
│  SBF-20 传输层                                           │
│  请求/响应帧、FLAGS 分片、双 opaque 流重组                 │
│  → 见 [传输层专版](./近场20B二进制帧串口协议-v2.0-传输层.md) │
└─────────────────────────────────────────────────────────┘
```

**应用层输入**：传输层交付的 **请求 opaque**、**响应 opaque**（各为一条 UTF-8 JSON 字节流）。

**应用层职责**：opaque 语义、JSON 读/写格式与业务 `code`。线帧、FLAGS、对超时等见 [传输层专版](./近场20B二进制帧串口协议-v2.0-传输层.md)。

### 1.2 与传输层的衔接

| 传输层交付 | 应用层解析 |
| --- | --- |
| 请求 opaque（请求帧 `PAYLOAD` 拼接） | `JSON.parse` → 读/写 **请求** 对象 |
| 响应 opaque（响应帧 `PAYLOAD` 拼接） | `JSON.parse` → 读/写 **响应** 对象 |

一次业务会话 = 传输层一个请求↔响应会话 = 应用层一条读或写命令。

线帧映射见 [传输层专版 §4.3](./近场20B二进制帧串口协议-v2.0-传输层.md#43-线帧通道与-opaque-映射)。

**探活**：传输层空 opaque 一对；应用层判定链路可用即可（无 JSON）。

**与传输层角色边界**：传输层允许 **App 或 MCU** 担任发起方（[传输层 §1.3](./近场20B二进制帧串口协议-v2.0-传输层.md)）。**本文应用层规定** 仅适用于 **App 为传输层发起方**（表 1）的近场配置场景；MCU 在应用层 **恒为应答方**。

### 1.3 发起方与应答方（应用层）

| 角色 | 实现 | 应用层行为 |
| --- | --- | --- |
| **发起方** | **App** | 发起探活、读、写；请求 JSON 含 `op`；**不** 被动上报配置 |
| **应答方** | **MCU** | 解析请求 JSON；组响应 JSON（含 `code`）；**不** 主动发起会话 |

**记忆口诀**：**App 发 `op`，MCU 回 `code`；MCU 只应答，不主动推业务 JSON。**

## 2. 应用层能力一览

### 2.1 发起方能力（App）

| 能力 | 说明 |
| --- | --- |
| **探活** | 发空 opaque 会话；收到空 opaque 响应即链路可用 |
| **读配置** | 组 `{"op":"read","configs":[...]}` → `readOpaque` |
| **写配置** | 组 `{"op":"write","params":{...}}` → `writeOpaque` |
| **解析读响应** | `{ code, params }`；`code=0` 合并 `params` |
| **解析写响应** | `{ code, message? }` |
| **变长编码** | 紧凑 `JSON.stringify` → UTF-8 |
| **读会话续收** | 估算 `N_rsp`，请求发完后可发 **空请求帧** 续收响应（§8） |

App 实现见 [近场JSON完整说明.md](../Logic/近场JSON完整说明.md)、[SBF-20近场协议App实现说明.md](../Logic/SBF-20近场协议App实现说明.md)。

### 2.2 应答方能力（MCU）

| 能力 | 说明 |
| --- | --- |
| **响应探活** | UART RX 收空 opaque 请求 → UART TX 空 opaque 响应 |
| **解析请求** | 请求侧 `MORE=0` 后 `JSON.parse`；识别 `op` |
| **读配置** | 查 Flash → 组 `{"code":0,"params":{...}}` → 响应侧分片 |
| **写配置** | 校验并写 Flash → 末对响应侧回 `{"code":0}` 或错误 JSON |
| **读会话** | 收齐读请求后再发响应 JSON；中间对响应 `PAYLOAD` 可为空 |
| **写会话** | 收齐写请求后于 **末对** 响应侧回结果 JSON |

MCU 传输层实现见 [传输层专版 §10](./近场20B二进制帧串口协议-v2.0-传输层.md#10-mcu-固件实现)。

### 2.3 双方共同遵守的应用契约

| 契约 | 说明 |
| --- | --- |
| **唯一格式** | opaque 为 **UTF-8 JSON 文本** |
| **变长** | `N` = 实际 UTF-8 字节数；`K = ⌈N/15⌉` |
| **双 opaque** | 请求 JSON 与响应 JSON **独立**；各 `JSON.parse` 一次 |
| **响应字段** | 响应含 `code`；读含 `params`；可选 `message` |
| **业务结果** | 成功与否由响应 `code` 表达 |

## 3. 术语

| 术语 | 含义 |
| --- | --- |
| **发起方** | App；发出含 `op` 的请求 JSON |
| **应答方** | MCU；发出含 `code` 的响应 JSON |
| **请求 JSON** | 发起方 → 应答方的应用消息 |
| **响应 JSON** | 应答方 → 发起方的应用消息 |
| **identifier** | 物模型参数键名（如 `sampleInterval`） |
| **config 组** | `configs[].identifier`（如 `samplingConfig`） |
| **N_req** / **N_rsp** | 请求 / 响应 JSON 的 UTF-8 字节数 |
| **K** | `⌈N/15⌉`，单侧 opaque 分片数 |

---

## 4. 编码与长度

| 项 | 规定 |
| --- | --- |
| 字符编码 | **UTF-8** |
| JSON 格式 | 紧凑序列化（无空格换行） |
| 长度 | **变长** |
| 分片 | 传输层 FLAGS；应用层只解析重组后 JSON |
| **MCU 缓冲建议** | 单侧 opaque **1～4 KB**；超长回 `code=1` |

| `N`（B） | `K = ⌈N/15⌉` | 典型消息 |
| --- | --- | --- |
| 41 | 3 | 读响应 `{"code":0,"params":{"sampleInterval":30}}` |
| 42 | 3 | 读请求 `{"op":"read","configs":["samplingConfig"]}` |
| 45 | 3 | 写请求 `{"op":"write","params":{"sampleInterval":60}}` |
| 10 | 1 | 写响应 `{"code":0}` |

---

## 5. JSON 消息格式

### 5.1 读请求（发起方 → 应答方）

```json
{"op":"read","configs":["samplingConfig"]}
```

| 字段 | 类型 | 规定 |
| --- | --- | --- |
| `op` | string | 固定 `"read"` |
| `configs` | string[] | 配置组 identifier；`[]` 表示读全部可见项 |

### 5.2 写请求（发起方 → 应答方）

```json
{"op":"write","params":{"sampleInterval":60,"displayBrightness":50}}
```

| 字段 | 类型 | 规定 |
| --- | --- | --- |
| `op` | string | 固定 `"write"` |
| `params` | object | 键为 TSL `identifier`，值为待写入值 |

### 5.3 读响应（应答方 → 发起方）

```json
{"code":0,"params":{"sampleInterval":30,"uploadPeriod":60}}
```

| 字段 | 规定 |
| --- | --- |
| `code` | `0` 成功；失败见 §10 |
| `params` | 读回的参数键值对 |
| `message` | 可选 |

### 5.4 写响应（应答方 → 发起方）

```json
{"code":0}
```

```json
{"code":2,"message":"flash_busy"}
```

| 字段 | 规定 |
| --- | --- |
| `code` | `0` 成功；失败见 §10 |
| `message` | 可选 |

### 5.5 请求 / 响应对照

| `op` | 请求 JSON | 响应 JSON |
| --- | --- | --- |
| `read` | `{"op":"read","configs":[...]}` | `{"code":0,"params":{...}}` |
| `write` | `{"op":"write","params":{...}}` | `{"code":0}` 或 `{"code":2,"message":"..."}` |

| 语义 | 请求 opaque | 响应 opaque |
| --- | --- | --- |
| **读配置** | 读请求 JSON | 读响应 JSON |
| **写配置** | 写请求 JSON | 写结果 JSON |

## 7. 写配置会话（应答方 MCU 必读）

写请求 JSON 在 **请求侧** 分片；写结果 JSON 在 **响应侧** 末对回传。

| 对（INDEX） | 请求 `PAYLOAD` | 响应 `PAYLOAD` | 响应 `FLAGS.MORE` |
| --- | --- | --- | --- |
| 0 ～ K-2 | 写请求 JSON 片段 | **空** | **1** |
| K-1（末对） | 写请求末片段 | 写结果 JSON | **0** |

| 角色 | 规定 |
| --- | --- |
| **发起方（App）** | 拼接全部响应 `PAYLOAD` 后 `JSON.parse` |
| **应答方（MCU）** | 中间对：响应 `PAYLOAD` 为空、`MORE=1` |
| **应答方（MCU）** | 请求侧 `MORE=0` 时解析写请求并写 Flash |
| **应答方（MCU）** | **末对** 响应侧放入 `{"code":0}` 或错误 JSON |
| **双方** | 末对请求与响应的 `FLAGS.MORE` **均为 0** |

### 7.1 写配置示例

写 `{"op":"write","params":{"sampleInterval":60}}`：`N_req=45`，`K=3`。

| INDEX | 请求 MORE | 请求 PAYLOAD | 响应 PAYLOAD | 响应 MORE |
| --- | --- | --- | --- | --- |
| 0 | 1 | 15 B | 空 | 1 |
| 1 | 1 | 15 B | 空 | 1 |
| 2 | 0 | 15 B | 10 B（`{"code":0}`） | 0 |

响应末片线帧：`55 0c 03 7b 22 63 6f 64 65 22 3a 30 7d f8`

SSCOM 见 [SBF-20-SSCOM测试用例.md](../Debug/SBF-20-SSCOM测试用例.md)。

## 8. 读配置会话（应答方 MCU 必读）

读请求 JSON 在 **请求侧** 分片；读结果 JSON 在 **收齐读请求后** 于 **响应侧** 分片下发。

| 阶段 | INDEX | 请求 `PAYLOAD` | 响应 `PAYLOAD` | 响应 `FLAGS.MORE` |
| --- | --- | --- | --- | --- |
| 收读请求 | 0 ～ K-2 | 读请求片段 | **空** | **1** |
| 读请求末片 | K-1 | 读请求末片段 | 响应首段（≤15 B） | 响应未完：**1**；仅一段：**0** |
| 续收响应 | K ～ | **空**（发起方续发） | 响应续段 | 末段：**0** |

| 角色 | 规定 |
| --- | --- |
| **应答方（MCU）** | 收齐读请求前：响应 `PAYLOAD` 为空、`MORE=1` |
| **应答方（MCU）** | 收齐后组 `{"code":0,"params":{...}}`，按 15 B 分片从读请求末对或下一对起下发 |
| **应答方（MCU）** | 末片响应 `MORE=0` |
| **发起方（App）** | 读请求发完后，若响应 `MORE=1`，须发 **`PAYLOAD` 为空的请求帧** 逐对收取后续响应 |

### 8.1 读配置示例（与传输层 §7.3 示例 C 一致）

读请求 `{"op":"read","configs":["samplingConfig"]}`：`N_req=42`，`K_req=3`。  
读响应 `{"code":0,"params":{"sampleInterval":20,...}}`：`N_rsp=44`，`K_rsp=3`。  
**共 5 对**。

| INDEX | 请求 MORE | 请求 PAYLOAD | 响应 MORE | 响应 PAYLOAD |
| --- | --- | --- | --- | --- |
| 0 | 1 | 15 B | 1 | 空 |
| 1 | 1 | 15 B | 1 | 空 |
| 2 | 0 | 12 B | 1 | 15 B |
| 3 | 1 | 空 | 1 | 15 B |
| 4 | 0 | 空 | 0 | 14 B |

### 8.2 MCU 应答方收发包摘要

| 会话 | MCU（应答方）行为 |
| --- | --- |
| **探活** | RX `55 02 00 df` → TX `55 02 00 df` |
| **写配置** | `INDEX` 0～K-2：响应空载荷、`MORE=1`；末对：响应含 `code` JSON、`MORE=0` |
| **读配置** | 收齐请求前响应空；之后按 §8.1 表分片下发；**空请求帧** 仍须回响应片 |

| 规则 | 规定 |
| --- | --- |
| 中间片 | 该侧 `FLAGS.MORE = 1` |
| 末片 | 该侧 opaque 发完时 `FLAGS.MORE = 0` |
| 解析时机 | **写**：请求侧 `MORE=0` 后可解析请求 JSON；**读**：请求侧 `MORE=0` 后组响应 JSON |

## 9. 重组与解析

| 步骤 | 发起方（App） | 应答方（MCU） |
| --- | --- | --- |
| 1 | 传输层拼好 opaque | 同左 |
| 2 | `TextDecoder` → 字符串 | UTF-8 解码 |
| 3 | `JSON.parse` | `cJSON` 等 |
| 4 | 读：取 `params`；写：取 `code` | 按 `op` 执行业务后组响应 JSON |

| 规则 | 规定 |
| --- | --- |
| 请求缓冲 | 拼接请求帧 `PAYLOAD`；请求侧末片后解析 |
| 响应缓冲 | 拼接响应帧 `PAYLOAD`；响应侧末片后解析（发起方）或末对组帧（应答方） |

## 10. 业务错误码（`code`）

| `code` | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 参数校验失败 |
| 2 | Flash 写入失败 |
| 3 | 未知配置或参数 |
| 4 | JSON 解析失败 |

失败示例：`{"code":2,"message":"flash_busy"}`。

App 常量：`Admin.NET-v2/App/utils/nearField/nearFieldConfig.js`。
